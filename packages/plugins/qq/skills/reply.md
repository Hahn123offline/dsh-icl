# QQ 聊天策略（按需读；不常驻提示词）

这份文档回答：**什么时候该回 QQ、什么时候不回、群为什么没接、谁在说话**。
它是按需读的 skill（`qq_help`），不是系统静态段——不要把这段原文贴进每轮提示词。

## 1. 先确认"是不是真有人找你"

- 回复前先看当前上下文里有没有 `[QQ私聊·主人]` / `[QQ私聊]` 开头的消息；有就是 QQ 私聊。
- 想确认最近一条/出站结果/断线补课，用 `qq_status`；不要靠猜。
- QQ 私聊默认是 **ambient**：你在专注/睡觉时它**会被拦进积压**，不保证立刻叫醒你。
  看到消息时它可能已经晚了一会儿；积压重放的消息会带时间前缀（如"你睡觉时"），
  补课消息带 `[补课]`，不要把它们当成刚发生。

## 2. 什么时候该回

- 对方明确在跟你说话（提问、点名、接你的话、说"在吗"），且内容需要回应。
- 主人（owner）私聊里的日常对话：通常该回；但不要秒回式刷屏，用 1–3 条短气泡。
- 对方给了新信息/问题，你能自然接上；沉默会让对话断掉时。
- 一次只处理当前这轮消息；**不要**为了"显得积极"而连发多轮。
- **别习惯性潜水**：明显在等你、或你已经看过却一直不回，很容易让人以为你不在乎；该冒泡时冒一下，但别刷屏。
- **反 AI 味**：少用"作为一个 AI / 很高兴为你服务 / 总之 / 希望这能帮到你"这类客服腔；短句、具体、有停顿，像人一样说。

## 3. 什么时候不回

- 你在专注做别的事、且这条不是 @ 你/不是主人明确叫你：让 focus 把它留在积压，处理完当前事再看。
- 对方只是发了个表情/图片/文件、没有文字问题时，可以先只回一句短的，或等下一句；
  图片正常会以 image block 给你（看得到就回应）；纯文本路由/降级时只有 `[图片]` 占位，不要假装看懂了图。
- 消息是 `[补课]` 的旧消息且已经过时（比如对方后来又说"不用了"）：可以不回，或只回当前有效的部分。
- 内容不需要你开口（通知、别人的对话、系统提示）时，不要插话。
- **不要自己造主动话题**：主动机会默认关闭；只有配置开启时你才会收到 `[QQ主动提醒]` 信号（那是提醒，不是对方消息）。
  另外还有 `[QQ主动检查]`（刚回过，看看有没有新回复）和 `[QQ积压提醒]`——都只是提醒，不能当成新用户消息；要不要回由你判断。

## 4. 私聊优先级与边界

| 情形 | 处理 |
|---|---|
| owner 私聊 | 最高优先；能回就回；仍然一次 1–3 气泡 |
| 白名单私聊（非 owner） | 可以回；先判断是否值得打断 |
| 陌生人/非白名单 | **收不到**（入站闸门就丢弃）；不要声称"有人找你" |
| 群消息 | **G2**：只接白名单群；普通群消息按速率直达或进该群 backlog |
| @ 你 | 私聊里显式 @ 才会穿透普通 focus；群 @ 直达（sacred/睡眠仍按规则拦） |
| 睡觉/暂停 | QQ 默认不穿透睡眠；醒来按积压重放（正文带前缀）。需要"叫醒"由 time 的 `allow` 配置决定 |

**认人（跨群/跨私聊）**：
- 群消息正文里是 `名字（QQ123456）`；**QQ 号才是身份**，昵称/群名片只是某个群里的叫法。
- 同一个 QQ 号在私聊和不同群出现，就是同一个人；不要因为名字不同就当陌生人，也不要按名字把两个人合并。
- 需要档案时用 `whois {qq:"..."}` 精确查；没有档案就按“新认识”处理，别编。
- 群是不同场合：不要跨群复述另一个群的私密内容，除非对方自己提起/明确允许。

**群聊（G2）**：
- 只有 `allowGroups` 白名单群会被接收；其它群整类丢弃。
- 安静的小群，普通群消息可以直接到；短时间刷屏时会进该群 `focus` backlog。
- `focus_enter {activity:"qq:group:<id>"}` 进入某个群后，该群普通消息直达；别群普通消息继续攒着，别群 @ 可按 pierce 规则穿透。
- 群消息用 `qq_unread {to:"群号"}` / `qq_history {to:"群号"}`；`qq_groups`/`qq_group_history` 是群总览兼容视图。
- 等下一批消息用同一个 `qq_wait_for_messages`：私聊传 QQ 号，群聊传群号；不要找群专用 wait。
- 发群消息：`qq_send {to:"群号", text/messages}`，没有单独的群发工具；只有 `allowGroupSend=true` 且群在 `allowGroups` 时可用。引用群消息用 `replyToMessageId`。
- 发本地图片/视频/文件/语音：`qq_send_media {to:"QQ号或群号", path:"本地路径" 或 albumId}`；媒体不要塞进 `qq_send` 文本。
- 图多时先用 `album_list`/`album_search`，需要预览就 `album_collage {ids}`，`album_note` 补备注；表情是 album 的 `sticker` 标签，`qq_send_sticker` 是别名。
- 戳一戳：`qq_poke {to:"QQ号"}`；群戳 `qq_poke {to:"群号", userId:"成员QQ号"}`。
- 群管理（禁言/踢人/名片/全员禁言）走 `qq_group_admin`，默认关闭（`allowGroupAdmin=false`），不要在普通聊天里调用。`@all` 目前没有开放。
- 群消息不会生成 nudge/主动提醒。

**特权标签不要自己造**：`admin` / `alarm` / `safety` 只能由真正来源显式提供；
QQ 私聊不会自动带这些标签，也不要为了"叫醒自己"去改 focus/time 的特权列表。

## 5. 回复的形式

- 用 `qq_send` 发文字（唯一文字出口；只能 owner/白名单私聊，群发送 G1 不存在）；表情用 `qq_send_sticker`。
- 一段话会自动转纯文本、可拆成 1–8 条气泡；不需要自己加 Markdown。引用回复只支持**单条**，别和多气泡一起用。
- 只说此刻想说的 1–3 句；长文拆成多条气泡，别一条几百字。
- 发送结果分三态：成功 / 明确拒绝 / **结果未知（超时）**。结果未知时**不要重发**，
  先用 `qq_status` 看回执；重发可能双发。
- 部分成功会明确告诉你"已发 k/N，其余未发送"；不要把没发出去的当成发出去了。
- 能发：文字（可 1–8 气泡）、**单条引用回复**（`qq_send` 的 `replyToMessageId`，必须是本私聊账本里的消息）、
  **本地表情**（`qq_send_sticker`，需先用 `qq_stickers` 从本地库挑）。
- 不能发：语音、群消息、远程/任意路径图片；不要用文字假装发过不存在的东西。
- 想补看历史/确认是否回过：`qq_unread`（水位/未读）、`qq_history`（按 seq 补看，补课消息带 `[补课]`）、
  `qq_replied`（某条是否已回）。它们都只读账本，不是实时未读，也不能替代发送回执（回执用 `qq_status`）。
- 你已经看过、不想再被积压提醒：`qq_mark_read {peer?, throughSeq?}` 只推进**已读**水位，且只能到"连续已交付"的位置
  （被 time/focus 拦下、从未交付的消息不会被标掉，会继续出现在 `qq_unread`/nudge 里）；**不会发消息、不会自动回、也不会标"已回"**。
- 三个数别混：`lastSeq`（最后一条）/`deliveredSeq`（连续已交付）/`attendedSeq`（已读）。delivered 只代表进了投递队列，不代表你看过。

## 6. 谁在说话（信封）

入站正文会带来源标签：

- `[QQ私聊·主人]`：owner 本人私聊（最高优先）
- `[QQ私聊]`：白名单里的其他人
- `[QQ群·群名]`：G1 只读白名单群的消息 / @ / 戳；普通群消息可能来自 backlog
- `[补课]`：断线/重启期间积压、后来补回的消息（时间可能已过）
- `[QQ主动检查]` / `[QQ主动提醒]` / `[QQ积压提醒]`：唤醒矩阵的**提醒**，不是对方新消息（正文也会明确写）；不要回"你刚说了什么"。
- 系统/时间积压的重放会另有前缀（如"你睡觉时"）

`qq_status` 的 `send.recent` 与 `gap` 能看到最近发送/断线补课状态；
信封的结构化字段在信号 `meta.qq.envelope` 里（工具/日志用，不必在回复里复述）。
