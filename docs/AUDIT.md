# ICL 复盘（2026-11-01）

## 一、已经完整闭环的

| 链路 | 证据 |
|---|---|
| 记忆写入 → 抽取 → 成块 → 引用 → 疑问 → 纠正 → 召回 | 109 测试；回放 5 天 170 条，召回 8/8；压测 95% |
| 工具面：注册 → 描述装配 → 索引 → 卸载 | `tool-constraints`、`host` 测试 |
| 模型接线：形状匹配 → 绑定 → 真实调用 | `wire-check` 实测 chat 0.4s / embed 1024 |
| 消息投递：唯一出口 + ack/nack | `delivery` 测试；插件无 `ctx.push` 调用 |
| 补充上下文：`prompt.onTurn` → 核心统一装配 | `eager-recall` 测试（投递队列为空） |
| 人物：档案 → 逐句引用 → 身份路由 | `whois`、`route-person` 测试；claims 6/3/4 条 |

## 二、健康的可扩展性

- 核心只有 6 个服务：tools / prompt / focus / delivery / slots / raw + model 客户端
- 插件只声明**形状**（`{kind, dim}`），不写模型名、地址、密钥；边界测试在守
- 每个插件 `apply(ctx)` 返回 disposer，停用即回收（动态工具面有测试）
- 加工具 = 发一条结构化约束（summary/when/avoid），描述由核心拼装并限长
- 新增能力（note、dsh-raw、eager-recall、whois）都是独立插件，核心未改动语义

## 三、潜在违规 / 风险

| 风险 | 现状 | 严重度 |
|---|---|---|
| 事件 job 只要有任一块写出，就把当天**全部** note 标已消化 | 部分覆盖会丢细节（原文层可救，但 note 不可召回） | 高 |
| 人物路由用"短查询 + 档案子串"判定 | 两字事件词若出现在人物档案里，会被误判为查人 | 中 |
| `dsh-raw` 直接读 `~/.dsh/sessions` 布局 | 边界测试只查 import，不查文件耦合 | 中 |
| `dsh-raw` 把会话日志全量读进内存缓存，无淘汰 | 会话多时内存增长 | 中 |
| `focus` 服务没有任何插件使用 | 有 bit-rot 风险，或被误认为已具备 | 低 |
| 插件里混用 `ctx.now()` 与 `Date.now()` | 时间不可注入，测试易脆 | 低 |

## 四、建立一个 ICL 会话得到什么

1. 一套零默认工具的会话：工具面由插件决定，可随时增减
2. 一条受控的消息出口（ack/nack、批合并、恰好一次）
3. 可插拔的模型（形状匹配，不绑厂商）
4. 长期记忆：抽取、成块、逐句引用、原文兜底、疑问闭环
5. 每轮自动召回（阈值可调、可关）
6. 世界状态简报（被动读取）

## 五、与旧 ICL 的差距（决定是否返工核心）

旧 ICL 的插件：`persona-inject`、`memory-inject`、`world-inject`、`tools`、
`icl-compaction`、`fold-runner`、`observer`、`session-guard`。

| 旧能力 | 新 ICL | 差距性质 |
|---|---|---|
| 人格注入 | ✅ persona | 已覆盖，且更强（版本/回滚） |
| 记忆注入 | ✅ eager-recall + recall + whois | 已覆盖，且更强（证据/原文） |
| 世界注入 | ✅ world-state | 基础版（无 attention/timers） |
| 工具注册 | ✅ 核心通道 | 已覆盖，且更强（约束装配） |
| **上下文压缩 / fold** | ❌ 无 | **核心缺口：没有"历史访问 + 改写上下文"的契约** |
| **session-guard** | ❌ 无 | 插件可做，但需要"本轮信息"的注入点 |
| **observer（事件/注意力）** | ❌ 无 | 需要 DSH 入站事件的归一化契约 |
| QQ / MC / Bili 连接器 | ❌ 无 | 集成层，不属于核心 |

## 六、结论

- **不需要返工核心**：现有 6 个服务足以支撑已完成的全部能力。
- **需要一次"加法式"核心扩展**：给插件一个**上下文/历史契约**
  （读取本轮历史、注册压缩策略、在装配前改写），否则 compression、fold、
  session-guard、observer 都只能在插件里各自 hack。
- 其余差距（连接器、工具广度）都是插件层，按契约逐个补即可。
