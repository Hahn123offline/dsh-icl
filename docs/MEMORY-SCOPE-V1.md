# ICL 记忆 V1 范围与验收（Scope & Definition of Done）

- 状态：**提案，待用户拍板**
- 日期：2026-11-13
- 目的：给记忆功能定"完成线"和"过度开发红线"，避免需求/补丁无限扩张。
- 原则：**功能完善 ≠ 继续变好**；到达验收线后进入维护，只有"新需求"才能开启新开发。

---

## 1. 需求重述（我们到底要什么）

ICL 是长期陪伴型 Agent，记忆要服务四件事：

1. **记得共同经历**：一起做过的事、说过的话、当时的情绪与结果（episode 为主）；
2. **该想起时想得起**：主动问过去能答，话题碰到旧事时能被提示；
3. **知道自己记得什么**：有记忆自知，没记忆时诚实说没有，不编；
4. **可纠正、可恢复**：能忘/能改，系统可重建、可回滚、可观察。

**明确不做**（v1 非目标）：
企业级多租户记忆平台、通用知识库、复杂图推理、多 Agent 共享记忆、记忆可视化 UI、procedural memory 训练、
云端同步、把 v2 继续迭代。

### 2.2 规模与"过度迹象"

- 记忆相关代码约 **10k 行**（dream 3.2k、recall 1.1k、eval 1.8k、corpus 工具 2.4k、memory 0.5k）；
- 近 3 天做了 **10 轮增强**（v3 重建、热迁移、自知、意图路由、跨天去重、QQ 修复、语义指标、方差）；
- 出现了 **按探针逐个修规则** 的苗头（噪声笔记过滤、人物配额、eager 语义阈值、候选池大小），
  虽然每条都能解释，但节奏说明"再修一点"的边际收益在下降；
- 评测工具面已经很大（大量 flag、语义审计、方差），继续扩会变成"评测开发"而非产品开发；
- v2 双路径（events/typed 召回代码）仍在维护，是长期负担。

**结论：功能面已基本齐，应该冻结并验收，而不是继续加能力。**

## 3. 参考实现：借鉴什么、不借鉴什么

| 系统 | 核心做法 | 借鉴 | 不借鉴 |
|---|---|---|---|
| [Mem0](https://docs.mem0.ai/migration/platform-v2-to-v3) | 抽取原子事实，ADD/UPDATE/DELETE/NOOP，向量+图存储 | 记忆操作语义、去重/更新纪律、[评测方法](https://mem0.mintlify.app/core-concepts/memory-evaluation) | 原子事实作为主单位（破坏陪伴叙事的连贯性）；平台化 API |
| [Letta / MemGPT](https://docs.letta.com/v1-sdk/memory/context-hierarchy) | 上下文内 memory blocks + archival memory，Agent 自编辑记忆 | "记忆块 + 归档"分层、自编辑/自知 | Agent 每轮自主管理记忆（成本/漂移不可控） |
| [Zep / Graphiti](https://github.com/getzep/graphiti) | 时序知识图谱、双时间轴事实有效性 | 事实的"有效期/被取代"意识 | 完整图数据库（当前规模不需要） |
| [A-MEM](https://export.arxiv.org/abs/2502.12110) | Zettelkasten 式笔记 + 动态链接 | episode 之间"相关经历"链接的构想 | 以链接为核心（我们已有 episode 主单位） |
| [LangMem](https://www.langchain.com/blog/langmem-sdk-launch) | semantic/episodic/procedural 三类记忆 + 后台整理 | 类型学清晰、后台 consolidation | procedural 训练、SDK 平台化 |

**我们的定位**：陪伴型 Agent 的"粗粒度情节记忆 + 轻量人物/关系/词汇"。
V1 不追研究前沿，只保证四条需求在 live 上稳定成立。

## 4. 功能完善（V1 Release Gate）

"功能完善"= **所有 P0 用户旅程跑通 + 固定质量/运维门槛达标 + 可回滚**。
不是"没有可改进空间"。

### 4.1 P0 用户旅程（必须全过）

| 编号 | 旅程 | 验收方式 |
|---|---|---|
| J1 | 当天聊完 → 夜里形成 → 次日能回忆 | 端到端剧本：fixture 日 + 3 个问题，anyHit=3/3 |
| J2 | 问过去细节/事件 → recall 答对 | 三源 anyHit@5 ≥95%，live miss=0 |
| J3 | 话题碰到旧事 → eager 注入或低置信提示 | 6 条 eager 探针（含"语义对但衰减旧"用例）≥5 命中；人工抽 20 条日志，注入相关率 ≥70% |
| J4 | 问人/关系 → 档案与关系正确 | person/relationship 探针 anyHit@5 ≥95% |
| J5 | 群梗/词汇能理解 | 10 个 term 人工抽审，有意义 ≥8 |
| J6 | 问"你记得什么/最近整理了吗" → 诚实状态 | world 记忆行 + memory_status 冒烟 |
| J7 | 没记忆时明确说没有，不编 | 人工标注的"应空"集（≥6 条）误注入 ≤10% |
| J8 | 用户要求忘/改 → 生效 | remember→forget、resolve 两条剧本 |
| J9 | 重建/备份/回滚可用 | 备份恢复演练 1 次（lab 同构） |
| J10 | 数据增长/延迟可控 | 见 4.3 |

> 当前缺口：J3 探针只有 1 条、J7 的"应空"集只有 2–3 条且部分标错（QQ p-09/live p-06 返回内容其实相关）。
> **补齐这些评测数据本身算 V1 验收准备工作，不算新功能**（上限：1 天工作量）。

### 4.2 质量门槛（固定基线，不再追涨）

| 指标 | 门槛 | 当前 |
|---|---|---|
| anyHit@5（focus / QQ / live） | ≥95% | 100 / 100 / 100 |
| strict recall@5（live / QQ） | 不低于 v2 基线 | 100 / 96.2 |
| strict recall@5（focus） | ≥85% | 90.6 |
| miss（live） | 0 | 0 |
| 语义 gold 覆盖（focus / live） | ≥75% / ≥90% | 78.1 / 100 |
| 语义 gold 覆盖（QQ） | 记录但不设门槛 | 30（已知弱） |
| 材料覆盖（focus / live） | ≥65% | 73.9 / 88.6 |
| 形成方差（episodes/5 天） | 稳定在 22–32；正文 350–460 | 26–29 / 371–428 |
| 空 query 误注入 | ≤10%（先修标注） | 待修标注 |

阈值一旦写入本文件，**只有出现用户可感知的失败**才允许上调要求；不允许为了数字继续调参。

### 4.3 运维门槛

- live 连续 **7 天**：dream job 成功率 ≥98%，无未处理异常；
- 召回延迟：评测 p95 <1s（当前 270–443ms）；eager 额外开销 <100ms；
- DB 增长：<20MB/月（当前 2.66MB 总量）；
- 每周 audit + 1 次人工 recall 抽审；备份保留 ≥2 份；
- 无密钥/隐私泄漏（audit 门禁 + 人工抽审）。

### 4.4 文档门槛

范围（本文件）、架构、运行手册、评测规范、变更日志、回滚演练记录各一份且与实际代码一致。

**满足 4.1–4.4 → 宣布"记忆 V1 功能完善"，进入维护模式。**

## 5. 过度开发红线（Stop Rules）

以下任一情况出现，必须停手、重新立项讨论：

1. **指标已达标仍继续调参**：anyHit≥95% 后继续优化 strict recall、MRR、单探针排序；
2. **为单个评测探针加规则**：任何 `if (probe/特定人名/特定词)` 式补丁；
3. **新增记忆类型/层**（taxonomy、概念记忆、procedural、图推理）而没有用户可感知失败 + 书面提案；
4. **默认开启额外 LLM 调用**（rerank、二次抽取、agent 记忆循环），除非 live A/B 证明 ≥5pt 收益且成本可接受；
5. **重写已工作子系统**（dream/recall）换 <5% 指标收益；
6. **UI/可视化/聊天功能**在 V1 验收前开始；
7. **多 Agent/共享/云端记忆**；
8. **继续维护 v2 双路径**：v2 只读冻结，不修不加（出现 P0 才动）；
9. **评测工具继续膨胀**（超过当前规模的新指标/新工具需审批）；
10. **"再来一轮增强"没有假设**：每个改动必须写清 baseline、假设、验收指标、回滚方式。

**变更预算**：冻结期后，维护模式每周最多 1 个改动；每个改动只服务一条已登记需求。

## 6. 确定安排（本案）

### R0 冻结与验收准备（即刻，约 1–2 天）
- 停止新功能；只做 V1 Gate 缺口：J3/J7 探针补齐与标注修正、J8 剧本、备份恢复演练；
- 不动产品行为（除非发现 P0 缺陷）。

### R1 观察期（7 天）
- live 只读观察：dream 成功率、episode/DB 增长、召回/eager 日志抽审、延迟；
- 每天 5 分钟检查，不改代码；发现 P0 才修（走变更预算）。

### R2 判定
- Gate 全过 → 宣布 V1 完成，打 tag，v2 冻结；
- 未过 → 只允许修复未过项，单项验收，不得顺手加功能。

### R3 后 V1（需单独批准，按需开启）
只保留 3 个候选，且各自独立预算：
1. **QQ 形成内容完整性**（当前语义覆盖 30%，仅当用户仍在意旧 QQ 素材才做）；
2. **时序有效性**（事实/关系有效期，仅当 live 出现"记错/过时"实例才做）；
3. **记忆查看/导出 UX**（用户要"看得到自己的记忆"时再做）。

其他方向（taxonomy、图、UI、多 Agent、本地大模型实验）**默认不做**。
