# 核心闭环：三段骨架

> 2026-11-03 定稿的优先级骨架。只列"闭环要用"的东西，不含 QQ/B站/MC 适配。
> 每段做完再做下一段，不并行。

## 闭环长什么样

```
醒来 ──→ 做事 ──→ 记住 ──→ 睡着整理 ──→ 再想起来
 ↑                                    │
 └──────────── 时间模块 ──────────────┘
```

七段现状：

| 段 | 状态 | 缺口 |
|---|---|---|
| 调度 | 只有"每晚一次" | 没有醒来、暂停、恢复、单实例、时区 |
| 行动 | 工具面/投递可用 | 没有会话控制（创建/停止/指向未跑通） |
| 感知 | raw 来源可用 | `.zstd` 未测 |
| 记录 | 完整 | — |
| 做梦 | 七个 job 全在 | 块粒度、时间优先、跨天去重、人物合并 |
| 回忆 | 四类召回可用 | 没有"今天发生了什么"概览 |
| 遗忘 | 只有权重衰减影响排序 | 没有归档/剪枝 |

## P0：能自己动起来（不做就没法测）

1. **时间模块**（正式插件，见 `docs/TIME-MODULE.md`）
   - 唯一能主动发消息启动会话的插件
   - 唯一提供系统时间的地方
   - 睡觉是一个特殊日程；做梦由睡觉调用，依赖很轻
   - 对 Focus 加锁与排队，穿透消息在它这里筛选/积压
   - 对外暴露统一 API（设计时器、暂停、恢复、立即执行）
2. **控制面**（时间模块的一部分，不是另起炉灶）
   - `status / pause / resume / dream_now` 四个动作，可脚本调用

## P1：记忆可信

3. **遗忘阶段**：块分页扫描 + 归档/剪枝（现在 cleanup 只看最近 60 个块）
4. **做梦 v1**：时间优先成块、跨天近似重复合并、人物合并
5. **回忆概览**："今天/最近发生了什么"单独一条路径

## P2：收尾

6. `compaction` 接进 DSH 并验证折叠
7. `focus` 二选一：接进时间模块，或删除
8. 做梦质量评估：真模型 + 固定语料

## 明确不在这一段范围

- QQ / B站 / MC 适配
- 正式 GUI
- 上线部署

## 判断标准

- P0 完成 = 会话能按日程自己醒来、自己睡下，外部能暂停/恢复，测试可重复
- P1 完成 = 记忆随天数增长不会腐坏（不重复、不膨胀、能忘）
- P2 完成 = 上下文有兜底，质量可评估
