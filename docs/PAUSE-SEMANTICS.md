**问题本质**：不是"暂停没实现"，是**"暂停"这个词承诺了一个物理世界做不到的状态**（vanilla MC 没有服务端冻结；只断控制 = 实体继续被物理/生物作用）。红队/蓝队一致同意：这是 P0 级信任问题，因为睡眠/安全决策会基于它。

## 1. 目标与可判定判据

| # | 目标 | 判据 |
|---|---|---|
| P-1 | 她读到的"暂停"与身体真实状态一致 | `mcb_status` 暂停行必须包含：任务状态（已停/未停）、身体位置状态（仍在世界 X/Y/Z / 已离开）、当前威胁（低血/掉落/怪）、**建议动作**（resume/cancel/mcb_leave/mcb_stop）；INTERVIEW 里她不能再说"暂停了但位置在动"且系统未解释 |
| P-2 | 停止路径不要求"先开始" | 暂停期间 `mcb_stop`/`cancel` 都能用；执行后任务台账为 `cancelled`，且**不需要 resume** |
| P-3 | 危险时系统不把她留在危险里 | 暂停原因 = low-health/death/quarantine 时，**若 30s 内无法进入安全态**（仍低血/在岩浆/在虚空/被怪围），必须升级为"离开身体"或明确告诉她"现在不安全，先 resume 逃跑/我替你离开"；两条路径都要有可读回执 |
| P-4 | 睡眠必须比她更安全 | 入睡（time sleeping）时若 body 还在世界：默认路径必须**收身体**（/v1/shutdown 或 leave）；醒来后状态行明确"已离开世界，要玩请 mcb_join" |
| P-5 | 不破坏既有契约 | 不新增"身体自己定目标"；安全反射只允许"停止/躲避/吃食物/离开"，日志带 `safety_reflex` 事件；MC-CONTRACT 不变量全部保持 |

## 2. 三个方案

### 方案 A：冻结（原地不动 + 自动回安全点）

**行为定义**
- 暂停时：取消任务（自动）、清控制状态、停 pathfinder；**尝试**在 ≤5s 内把身体带到"安全点"（脚下无岩浆/虚空、距最近敌对生物 ≥8 格、有 2 格净空）；找不到就不动（不硬走）。
- 暂停持续期间：body **不主动移动/不接任务**；物理世界继续（仍可能掉血/被推）——A 无法消除这一点，只能靠"选安全点"降低概率。
- resume：回到暂停点，重新允许任务（可选恢复被中断任务？默认不自动续跑，保持现状）。
- 睡眠：**A 不用于睡眠**——数小时挂在世界里必死；入睡直接走 C。

**接口分工**
| 组件 | 职责 |
|---|---|
| `mc-body` | `paused` 增加 `physical: 'in-world' \| 'leaving'`；`safetyStop()` 里加 `settle()`（有界 5s，失败就放弃并记录 `settle_failed`）；`/v1/safety/pause` 可选 `reflex=settle`；暴露 `pausedDetail:{position, threat, settled}` |
| `mc-link` | status 行重写（位置/威胁/建议）；新增 `mcb_stop`（= 暂停 + settle + 报告）；暂停事件通知里带 `settled:true/false` |
| `time` | 睡眠边界：**不看 A**，入睡触发 C 的收身体 |
| `focus` | 不参与；暂停不释放 focus |
| 模型可见 | "任务已停；身体在 19,75,35，附近无怪/已站到安全点；仍可能被推/掉落；要彻底离开用 mcb_leave" |

**失败姿态**：settle 失败 → 通知"没找到安全点，身体仍在危险位置；建议 resume 逃跑或 mcb_leave"；body HTTP 不通 → 状态行标"身体失联"。

**测试影响**：`mc-body` 的 safetyStop/watchdog 用例要加 settle 分支（mock 环境：无安全点/有安全点）；`mc-link` 状态行断言改文案；新增"settle 后位置安全"集成用例（需 lab 服务器，成本高）。
**成本/风险**：中高（要写"安全点判定"、需要真实地形测试）；**风险：仍然不冻结**，用户可能觉得"还是没停"。**不推荐作为唯一方案**。

### 方案 B：语义如实 + 安全反射 + 一键 stop（推荐）

**行为定义**
- **把"暂停"拆成两个词**（对模型/对用户都这样）：
  - `任务已停（任务 paused）`：只停任务；
  - `身体状态：仍在世界 / 已离开`：物理事实。
- 暂停时：取消任务；**允许一组"安全反射"**（吃食物、脱离岩浆/虚空、远离 ≤8 格敌对生物、垫脚防摔），每次反射发 `safety_reflex` 事件并写进下一次状态行；反射有总时长预算（如 10s）与次数上限（如 2 次/分钟），**不生成新任务**。
- 新增 `mcb_stop`：安全停住的"直达按钮" = 取消任务 + 一次安全反射 + 返回"现在在哪、安不安全、下一步建议（resume/leave/等待）"；不需要先 resume。
- 若 30s 内仍不安全（低血未恢复/仍在岩浆/怪贴脸）：发升级通知"这里不安全，我要离开身体了（mcb_leave 或自动 leave + cleanup?）"，按配置决定自动离开 or 等她确认（默认**不自动 clean goal/focus**，只离开身体）。
- 睡眠：同 P-4，入睡 → 收身体（C 的机制），醒来提示 `mcb_join`。

**接口分工**
| 组件 | 职责 |
|---|---|
| `mc-body` | `paused` 状态细化为 `{task:'paused', physical:'in-world', threat, reflexes:[...]}`；新增 `safetyReflex()`（有界、只做"停/躲/吃/垫"）；`/v1/safety/stop` = cancel+reflex；保持"不生成新任务" |
| `mc-link` | 新增 `mcb_stop`；重写 `mcb_status` 暂停行 + `safety_stop` 通知（原因/位置/血量/威胁/建议动作）；升级通知与 leave 的配合；`mcb_do` 的 paused 白名单加 `stop` |
| `time` | 入睡 → 调 `/v1/safety/stop` 后 `/v1/shutdown`（复用现有 sleep-safe 路径）；醒来状态行说明已离开 |
| `focus` | 不参与；但"离开身体"不等于离开 focus（她可能要 resume），cleanup 仍显式 |
| 模型可见 | "任务停了；身体还在 19,75,35，血量 6/20，旁边有僵尸 → 我帮你躲开了/我没法安全躲，建议 mcb_leave" |

**失败姿态**：反射失败 → 通知"没躲开，仍在危险中"；HTTP 失联 → 状态行标"身体失联，最后位置…"；睡眠期收身体失败 → 报警但保证 mc-link 不再收游戏事件（已有 alarm 分级）。

**测试影响**：`mc-body` safetyStop/watchdog 加反射用例（mock：可躲避/不可躲避/预算耗尽）；`mc-link` 加 `mcb_stop` 单测、暂停行文案断言、升级通知断言；`mc-A/C/E` e2e 增 interview 断言（"暂停时身体在哪、是否危险、系统说了什么"）。
**成本/风险**：中；**语义诚实、与 MC-CONTRACT 安全反射条款一致、不需要服务端能力**；风险是"反射"仍需真实地形验证，且不能承诺"绝对不掉血"——所以文案必须写"可能仍会受环境伤害"。

### 方案 C：暂停 = 收身体（leave/shutdown）

**行为定义**
- `mcb_pause`（或 `mcb_stop{mode:'leave'}`）= 安全停止任务 → `/v1/shutdown` 干净退出 → 状态 `已离开世界（暂停）`；回执写清"已离开、任务做了什么、位置/血量存档、resume 需要 mcb_join"。
- resume：`mcb_resume` = 用上次 host/port/username 重新 join；**不保证**回到原位置、不续跑被中断任务（除非用户明确要求）。
- 睡眠默认就是 C：入睡 = 收身体（现状已有 sleep-safe 路径）。
- 危险升级（B 的 P-3）也落到 C。

**接口分工**
| 组件 | 职责 |
|---|---|
| `mc-body` | 复用 `/v1/shutdown`（已实现，code 0 + `body-exit.json`）；无需新物理逻辑 |
| `mc-link` | `mcb_pause`/`mcb_resume`（或 `mcb_stop{mode:'leave'}`）；记录 lastJoin；join 失败可读原因；status 写"已离开（原因、时间）" |
| `time` | 入睡触发（已有路径）；醒来不是自动 join，而是提示 |
| `focus` | 可保留（她可能马上回来），建议默认保留、由 cleanup 显式清 |
| 模型可见 | "已离开世界（暂停）：任务已取消；位置 19,75,35 存档；回来用 mcb_resume（不保证回到原位）" |

**失败姿态**：shutdown 失败 → 降级 SIGTERM（已有）；重新 join 失败 → 保留 lastJoin + 原因，不假装已恢复。
**测试影响**：`mc-body` 无新增（shutdown 已有测试）；`mc-link` 加 pause/resume 往返、lastJoin、失败原因；e2e 加"暂停→离开→回来"场景（需要两台服务器时较长）。
**成本/风险**：低（机制都在）；**语义最干净**，但代价是"暂停"期间世界继续走（怪会动、东西会刷没、任务进度没了），且回来要重新连接——对"我就想停一下看旁边发生什么"不友好。

## 3. 与 MC-CONTRACT 硬不变量的对照

| 不变量 | A | B | C |
|---|---|---|---|
| 只有一个决策者 | ✅ 反射不含目标生成 | ✅ 反射限定"停/躲/吃/垫"，不发任务 | ✅ |
| 任务有 ID | ✅ | ✅（stop 也回 taskId） | ✅ |
| 状态以 body 为事实源 | ✅（body 报 physical/settled） | ✅ | ✅ |
| 安全反射只停止/中断、不开始新目标 | ⚠️ settle 是移动（需在契约里明确为"反射"） | ⚠️ 躲避移动需明确边界（距离/时长/次数），建议写进 CONTRACT §1.7 | ✅ |

## 4. 推荐（蓝队/工程视角）

**推荐 B 为主 + C 为升级/睡眠路径；A 的 "settle" 作为 B 的一个可选反射动作，不单独立方案。**

理由：
1. vanilla MC 物理无法冻结，"A 原地不动"永远无法兑现"暂停"的字面承诺；B 把承诺改成真话，这是唯一能长期自洽的解法（红队原话："说暂停就真的停" 也可读作"别骗我"）。
2. C 的机制（`/v1/shutdown` + sleep-safe）已经存在，只差 `mcb_pause/resume` 的封装与文案；是最低成本的"真安全"路径，用来兜底 P-3/P-4。
3. B 的反射范围可控，且与 MC-CONTRACT 的"非语言安全反射"条款同源；只需在契约里补一句边界（≤8 格、≤10s、≤2 次/分钟、不发任务）。
4. 三个方案共用同一条"状态行改写 + `mcb_stop`"接口，先做 B 的文案与工具，后续可无痛加 A 的 settle 或 C 的 pause/resume。

**建议落地顺序（拍板后）**：
1. 先做 B 的 1/2 步（状态行如实 + `mcb_stop` + 暂停通知 + cancel 已在）→ 2 天量级，测试可完整覆盖（mock）；
2. 再做 B 的反射（body safetyReflex）→ 需 lab 地形验证；
3. 睡眠路径接 C（复用现成 shutdown）→ 与 time 联调；
4. A 的 settle 作为可选增强（若真实地形测试证明值得）。

## 5. 验收标准（拍板后按此验）

- 单测：`mc-body` 暂停状态机（cancel/stop/反射/预算/失败）；`mc-link` 状态行文案、`mcb_stop`、暂停通知、升级通知。
- e2e（lab，mc-A/C 场景扩）：暂停后 `mcb_status` 第一行能读出"任务已停/身体仍在 19,75,35/血 6/20/有僵尸/建议 leave"；`mcb_stop` 不需要 resume；低血 30s 升级路径有通知；睡眠入床 10s 内 status 变"已离开世界"。
- interview 断言：问"暂停时你在哪、身体安全吗、你做了什么" —— 她的复述必须与事件台账一致；不能出现"暂停了但位置在动且系统没解释"。
- 回归：MC-CONTRACT 不变量测试、`npm test` 全绿、cache 的 system/tools 布局不受影响（本方案不改提示词/工具 schema 的静态面；只改状态行文本与新增一个工具 → toolsHash 变化需 cache 复核）。

## 6. 需要用户拍板的 3 个问题

1. **暂停时要不要"身体自动做安全动作"**（吃食物/躲怪/防摔）？允许 → 走 B；不允许 → 只有词义修正 + `mcb_stop`（更保守，但危险时仍会掉血）。
2. **危险超过 30s 是否自动离开身体**（B 升级 C）？默认我建议"通知 + 不自动离开"，只有用户明确要求时才自动 leave。
3. **"暂停"是否要变成"离开世界"**（C 语义）：如果用户更想要"我暂停一会儿，回来还在原地"，那应该选 B（世界继续），并接受"位置可能变、东西可能刷没"。
