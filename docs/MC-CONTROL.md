# MC 控制力度：脊髓与大脑

> 方向：底层只负责**机械执行**和**生死反射**；高层模型拥有目标、工具选择、背包与抽象指令。  
> 关键不是“谁更聪明”，而是**授权、抢占、报告、恢复**四件事。

## 1. 三层权限

| 层 | 谁 | 时间尺度 | 能做什么 | 不能做什么 |
|---|---|---|---|---|
| **L0 反射（脊髓）** | body | 毫秒~2 秒 | 受击/低血/溺水/岩浆/苦力怕贴脸/卡死时：后撤、上浮、吃、换武器、跳开、停止当前动作 | 不生成新目标、不探索、不聊天、不擅自开战到远处 |
| **L1 技能（小脑）** | body | 秒~分钟 | 寻路、挖、放、采集、跟随、吃饭、开箱等任务内的动作 | 不决定“为什么做”、不改变任务目标 |
| **L2 意图（大脑）** | ICL/LLM | 轮次级 | 选任务、定目标、管理背包、社交回复、决定继续/放弃/换目标 | 不直接控制每个 tick；不绕过安全策略 |

一句话：**L0 保命，L1 干活，L2 决定干什么。**

## 2. 反射的边界

L0 只在“人已经来不及反应”的场景接管：

- 受击、血量快速下降；
- 溺水/低氧；
- 站在岩浆/火/仙人掌/细雪里；
- 苦力怕贴脸；
- 寻路卡死超过阈值；
- 掉线/死亡。

反射动作必须：

1. **有界**：单次 ≤2 秒，最多一个目标；不追远、不挖矿、不建造；
2. **可逆/低伤害**：优先后撤、上浮、吃、挡，而不是“看到怪就冲”；
3. **不生成目标**：只处理当前威胁，结束后回到暂停状态；
4. **必报告**：`threat` / `action` / `result` / `taskId` / `epoch`，让大脑知道“我刚才 override 了”。

### 苦力怕不是“换最高伤害武器反击”

用户例子“切最高伤害工具并反击”适用于僵尸/骷髅；苦力怕贴脸的正确反射是**先退**，不是对刀。反射策略要按威胁类型：

- 近战怪：装备最优武器，格挡/后退/反击（按距离和血量）；
- 苦力怕：后退到安全距离，不主动贴；
- 远程：找掩体/蛇形后退/盾；
- 水中：上浮换气优先；
- 岩浆/火：先离开，不贪旁边的矿。

反射不是“战斗 AI”，是**保命策略**。

## 3. 命令租约（lease）

每个高层任务带：

```json
{
  "taskId": "t-1",
  "epoch": 7,
  "kind": "mine",
  "params": {},
  "safety": {
    "autoDefense": true,
    "autoEat": true,
    "autoEscape": true,
    "autoTool": true,
    "noFight": false,
    "fleeOnly": false
  }
}
```

- `epoch` 每次上层改意图就递增；
- L0 打断任务时，任务进入 `interrupted`，保留原 taskId/epoch 和进度；
- 上层恢复必须显式 `resume(taskId, epoch)`；**不能静默续跑**；
- 如果威胁仍在，body 拒绝 resume，并说明原因；
- 过期 epoch 的指令直接拒绝，防止“旧意图”在反射后复活。

## 4. 冲突规则

优先级：

1. **硬安全**：不能死、不能掉进岩浆、不能淹死；
2. **上层显式禁令**：`noFight` / `fleeOnly` / `dontBreak` / `stay`；
3. **当前任务**；
4. **默认风格**（自动换工具、自动吃）。

解释：

- 硬安全可以**中断任务**，但不能**推翻显式禁令**去开战；它只能选择禁令允许的保命动作（逃、挡、吃）。
- 上层说“别打，跑”，body 不会自动反击；它只会后撤/挡，并报告“我按 fleeOnly 做了”。
- 上层说“继续挖”，但怪贴脸：body 先保命，任务 `interrupted`，报告；上层决定是否 resume。
- 上层可以**改变策略**（`safety.fleeOnly=true`），但不能在反射执行中“抢方向盘”；反射结束后统一读新策略。

冲突必须留下记录：

```json
{
  "type": "reflex_override",
  "taskId": "t-1",
  "epoch": 7,
  "reason": "creeper-4m",
  "action": "retreat",
  "result": "safe",
  "brainIntent": "mine",
  "policy": { "fleeOnly": true }
}
```

## 5. 信息注入

L0 事件走 plugin-originated notice，不走 user：

- `threat`：类型、距离、血量、武器、当前任务；
- `reflex`：做了什么、结果、是否 override；
- `task_paused` / `resumed` / `failed`；
- `inventory_changed`（可选）；
- `stuck` / `reconnected` / `spawn_unsafe`。

频率：

- 紧急事件立即注入（可打断）；
- 普通进度合并，不刷屏；
- 同类事件限流，但保命事件独立配额（参考 MC agent 的 idle/danger 分开）。

## 6. 具身工具

高层要有“身体感”，但不该拿 40 个工具：

- `mcb_look` / `mcb_inspect`：看画面/射线/附近实体/背包；
- `mcb_say`：说话；
- `mcb_stop`：立即停；
- `mcb_equip` / `mcb_drop`：背包管理（可选，和自动换武器协调）；
- `mcb_task`：抽象任务。

原则：**高层决定“做什么/为什么”，body 决定“这一步怎么动”。**

## 7. 背包与工具归属

- 上层拥有：背包整理、保留/丢弃策略、默认装备、任务目标；
- body 拥有：反射时的临时换武器/吃/挡；
- 反射结束后，body 报告换过什么；上层可以恢复默认装备；
- body 不擅自丢东西、不整理背包、不建造。

## 8. 力度参数（建议默认）

| 参数 | 默认 | 说明 |
|---|---|---|
| `autoDefense` | on | 近身威胁可反击/后撤 |
| `autoEat` | on | 饥饿/低血时吃 |
| `autoEscape` | on | 岩浆/水/卡死时脱离 |
| `autoTool` | on | 反射时换最合适工具 |
| `noFight` | off | 上层可关自动反击 |
| `fleeOnly` | off | 只逃不打 |
| reflex 单次 | ≤2s | 超时升级给上层 |
| reflex 范围 | 4–6 格 | 不追远 |
| 报告 | 必发 | 每次 override 都留痕 |

## 9. 评估指标

- `override_rate`：每 100 任务被反射打断次数；
- `conflict_rate`：反射动作与上层意图冲突次数；
- `false_reflex`：误判威胁导致的多余动作；
- `resume_success`：反射后任务恢复成功率；
- `task_success` / `stuck_rate`；
- `brain_latency`：上层响应时间；
- 第三方观感：transcript 评审“像不像一个在玩的人”。

## 10. 结论

- **大多数时候让 bot 纯听上层**是可行的；body 只保留“保命反射”和“任务内技能”。
- 不要给 body 目标生成权；它一旦会“自己找事”，就会和上层意图冲突。
- 控制力度靠**策略字段 + 租约 + 明确抢占规则**，不是靠提示词求它听话。
- 反射要按威胁类型做，不是统一“换最高伤害武器反击”。
- 先做**只报告不接管**的观察模式，再开 `autoEscape`，最后才开 `autoDefense`；每开一级都看 conflict/false_reflex。
