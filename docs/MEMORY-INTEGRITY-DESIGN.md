# 记忆准确性：证据、疑问与人物档案的策略（设计稿，待拍板）

> 背景：用旧 QQ 日志回放时发现两类错误。
> 一是「周子涵」被写成女性（实际是男性），二是「郑皓元」说过一个「乐」字，被写成了
> 他叫「乐乐」。两类错误都不是"模型不够强"，而是**我们给的信息和约束不够**。

---

## 一、先归因：错误是怎么产生的

### 1. 性别错：人格提示词泄漏

`prompts/dream.md` 开头是：

> 你是"她"的记忆沉淀器……

摘要在写人物档时，会**不自觉地沿用"她"这个第三人称**。周子涵的档案里出现"她在复习……"，
更可能是这个泄漏，而不是从材料里推断出来的。

### 2. 名字错：没有证据要求

`郑皓元 说「乐」` 是一句玩笑/语气词。摘要把它当成"也叫乐乐"，是因为：
**没有任何机制要求"这个说法必须能在材料里找到出处"**。模型自由联想，就飘了。

### 3. 错误会传染

人物 job 的输入里有"以前提到过 TA 的事件块"（已经是摘要过的文本）。
一旦某一块写错，下一轮人物档案会把它当事实继续喂进去——**错误会复利**。

### 4. 缺"人"的元信息

我们给摘要的每行只有 `[qq=...] 名字: 内容`，没有告诉它：
- 这是谁说的（发言者）
- 名字是对方自称、群名片、还是别人叫的
- 不要推断性别、不要把语气词当名字

---

## 二、机制一：证据链（citation）

### 目标

任何一条记忆块，必须能回答：**"这件事是从哪句话来的？"**

### 数据结构

每条 note 与 block 都带 `data.evidence`：

```json
{
  "evidence": [
    { "type": "message", "id": 12, "quote": "郑皓元：乐" },
    { "type": "note", "id": 88 }
  ]
}
```

- `message`：回放时来自原始消息（replay 有 id）
- `note`：来自主会话的 remember（写入时有 id）
- 块与块之间引用时用 `block` 类型（图，不是树）

### 生产流程

1. **输入带 id**：喂给模型的每一行都有稳定编号
   ```
   [12] 周子涵(3429502459): 上课了先闭麦
   [13] 郑皓元(3862352984): 乐
   ```
2. **输出带 evidence**：抽取与做梦都要求输出 `evidence: [12, 13]`
3. **落地校验**：
   - 引用的 id 必须存在，否则丢弃该条
   - 一条块没有任何有效引用 → 标 `provisional: true`，并生成疑问（见下一节）
4. **展示**：`recall` 默认不显示引用（省 token），`whois` / 详情可显示"依据 N 条"

### 为什么这能治"乐乐"

模型必须写出 `[13]`，而 `[13]` 的内容是「乐」。人在审阅时一眼能看出"一个字不是名字"。
更重要的是：**模型自己在写 evidence 时会被迫回看原文**，这类联想会明显减少。

## 三、机制二：疑问区 / 待办（note 插件）

### 目标

- 主会话可以记"我自己临时想做的小纸条"
- 消化记忆时发现的**不确定**，也要有个地方落脚，并在合适的时候问出来

### 结构

新命名空间 `note`（**不参与 recall 检索**，避免污染记忆）：

```json
{
  "namespace": "note",
  "kind": "question | memo",
  "text": "周子涵是男是女？档案里写了'她'，但材料里没有明确说法。",
  "data": {
    "status": "open | resolved | dropped",
    "about": { "namespace": "person", "key": "person:3429502459" },
    "raisedBy": "dream:people | cleanup | session",
    "evidence": [...],
    "askedAt": null
  }
}
```

### 谁来写

| 来源 | 写入内容 |
|---|---|
| 主会话 | `note({text})`：自己的小纸条 |
| dreams（people/slang） | 证据不足、代词歧义、与旧档案冲突 → 疑问 |
| cleanup | 合并后仍不确定 → 疑问；纠正找不到落点 → 疑问 |

### 谁来消费

- `notes({status:'open'})` 列出
- 主会话用 `resolve_note({id, answer})` 回答；回答文本进入对应记忆（或直接改块）
- **不自动问**：不往对话里推消息，只在提示词里放一小段（最多 3 条、≤120 字），
  或者只在工具里可查——这条需要你定

## 四、机制三：人物档案的更新策略（防"越写越飘"）

现在的规则是"每天整块重写"。改成**有材料才写，没材料不硬写**：

```
触发条件（满足任一）：
  1. 有新的 person 笔记（未消化）
  2. 档案是 provisional，且距离上次重写 ≥ 2 天
  3. cleanup 提出了关于这个人的疑问/纠正
否则跳过，连模型都不调。
```

写入时的输入（这是你说的"能查更久远的记忆"）：

```
· 现有档案（profile + facts + familiarity + provisional）
· 今天的新笔记
· 最近 10 条"提到 TA"的事件块（带 evidence id）
· 更早的事实（facts，按时间）
```

规则：**没有新证据就不改已有句子**。模型只允许：
- 追加有证据的新事实
- 修正被新证据推翻的句子（必须带新 evidence）
- 没有任何新东西就输出 `{"profile": ""}`（表示"不改"）

## 五、输入卫生（这次错误的直接修复）

1. 摘要人格提示词里的「她」改成中性：
   > 你是记忆沉淀器。
   并明确：**不要用性别代词指代材料里的人，用名字或 TA。**
2. 每行材料都带：`[id] 名字(QQ): 内容`，并声明"名字原样保留，不要改写成昵称"
3. 明确禁止：
   > 不要把语气词、单个字、玩笑当成名字或称呼。
4. 旧档案作为参考时标注"可能含旧错误，**不要默认它是对的**"

## 六、需要你拍板的五个问题

1. **证据粒度**：消息级（一行一条）够，还是要到"哪句话里的哪个短语"？
   （我建议消息级，够用且模型写得动）
2. **疑问区是否进提示词**：只在工具里可查，还是每轮最多带 3 条进上下文？
3. **谁能关疑问**：只有主会话（人回答），还是整理轮也能自己判"证据够了"关掉？
4. **人物重写触发**：用我上面的三条（新材料 / provisional 超 2 天 / 被纠正），还是再加一个概率抽样？
5. **无证据的块**：直接降为 provisional，还是直接拒绝写入？
   （我建议降级 + 提疑问，不丢信息）

---

## 七、和已有设计的关系

- 这三件事都落在**做梦**这一层，不改变 recall/whois 的对外语义
- `note` 命名空间与 `resolve` 一样是"非检索区"，但 note 是**双向**的（人会看、会答）
- 证据链让"整理轮合并"更安全：合并两个块时，`evidence` 取并集；
  如果两个块证据互斥（同一件事说法不同），必须提疑问而不是合并

## 八、实现状态（2026-11-01）

已落地：

- `note` 插件：`memo` / `memos`，世界状态里一行“还有 N 件事没了结”，不进 recall
- 疑问来源：**事件 / 人物 / 整理轮都可以提**（不只人物）：
  - 块没有证据 → 提一条“没有出处”
  - 整理合并且不确定 → 提一条“记不准”
- 防“为填待办而填待办”的三道闸：
  1. 每轮最多 5 条
  2. 按文字去重（已有未结的同样问题不重复提）
  3. 只在具体触发条件下提（无证据 / 矛盾），不主动搜查疑点
- 人物档案回归验证：5 天回放产出 3 份档案，无性别误写（用 TA），
  周子涵与 Hahn123 被正确归为同一个 QQ，郑皓元不再被写成“乐乐”。
- 疑问已实际产生 3 条（都是“档案没有出处”）。
