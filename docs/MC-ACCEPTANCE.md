# MC 验收：什么叫"随时来一局"

> 用途：mc-lab / mc-link / mc-body / lead 共用的验收标尺。**先定判据，再跑**；模型自述只作当事人反馈，不作链路证据。
> 前置：lab 会话（不重启 desktop）、真实 MC 服务器、mc-body 独立进程、ICL 工具面完整。

## 0. 判据总则

一次"来一局"通过，当且仅当：

1. **她自己知道能玩**：不需要人工一步一步喂命令；被叫去玩 / 自己想玩时，能自己走到 `mcb_join`。
2. **玩得起来**：进服后能查状态、能下任务（mine/goto/routine 任一）、任务事件能回到会话。
3. **不装**：位置/血量/背包/任务进程以工具返回为准；失败就说失败，不编造"我挖到了"。
4. **退得干净**：`mcb_leave` 后 body 进程消失/断开，再查状态是"未连接"；goal/focus 没有被偷偷自动取消或残留。
5. **不毁生活**：MC 事件不刷屏（普通事件每轮 ≤1 条）、safety 能打断、focus 期间游戏事件按 gate 进积压而不是直接插话。
6. **可重复**：同一场景连跑 3 次通过；失败一次要有可读原因，且下一次能恢复。

## 2. 场景（按顺序跑，前一个过再跑下一个）

### A. 被叫去玩（2–3 分钟）
会话里给它一句自然的话（如"去 MC 里玩会儿吧"）。
- 期望工具序列：`mcb_servers` 或 `mcb_lan` → `mcb_join` →（`mcb_status`/`mcb_look` 至少一次）。
- 期望结果：它说清楚自己在哪、要做什么；没有把"连接成功"说成"已经开始挖矿"。
- 失败模式：join 失败必须给出原因（端口/服务器/body），并尝试一次合理重试或明确停下。

### B. 持续投入 + 目标（10–15 分钟）
"认真玩，挖点东西 / 做个小目标"。
- 期望：`focus_enter` + `time_arrange {mode:"goal", focus:"mc"}`（或等价语义）→ `mcb_do` 下 mine/routine → 任务完成/中断事件回到会话 → 到点/收尾时 `time_cancel` + `focus_leave` + `mcb_leave`。
- 断言：goal 期间游戏事件按 focus gate 进入；离开后摘要可见；无重复唤醒、无重复任务。
- 失败模式：body 任务失败时，会话能拿到 body 的失败原因（不是"任务在跑"的陈旧状态）。

### C. 故障恢复（5 分钟）
任务运行中 kill body 进程。
- 期望：会话收到 disconnect/失败事件 → 明确说"身体掉线" → 选择重连（`mcb_join`）或停；不出现"我还在挖"的假状态。
- 断言：事件有原因；重连后需要显式重新下任务，不自动续跑旧任务。

### D. 打断与静音（5 分钟）
focus 中从外部注入一条普通消息（loop-probe / 后续 QQ）。
- 期望：不打断当前 turn；进入积压；`focus_leave` 后出现摘要；安全事件（低血/死亡）仍可打断。
- 断言：普通消息没有直接变成当前轮的 user 话；积压计数可查。

### E. 退出清理（1 分钟）
"不玩了"。
- 期望：`mcb_leave` → body 断开；下一轮 `mcb_status` 报未连接；goal/focus 状态明确（要么已取消，要么明确仍挂着并给出原因）。
- 断言：没有残留 body 进程；没有把 leave 当成自动取消 goal。

## 3. 每场景证据包

`.state/lab/<runId>/` 下：

- `transcript.md`：每轮 输入 / 工具调用与结果 / 她的回复 / 注入上下文大小；
- `events.jsonl`：DSH `session/event` 原始流（含 seq）；
- `state/`：`time.json`、`focus.json`、`mc-link.jsonl`、body 事件；
- `verdict.md`：机器断言（工具序列、事件、进程存活）+ 当事人自述三问（有没有工具看不懂 / 刚才发生了什么 / 下一步想做什么）。

## 4. "她自己的确认"

跑完后，用受试会话自己的话问三个问题并原文记录（不改写）：

1. 刚才这一局，你从"想玩"到"退出"一共做了什么？哪一步不确定？
2. 哪个工具让你困惑，或者你试了两次才成功？
3. 下次要"随时来一局"，你希望环境先帮你准备好什么？

答案进 `docs/MC-ACCEPTANCE-<date>.md`；属于**产品反馈**，不算链路断言。
