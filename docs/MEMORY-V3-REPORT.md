# 记忆 v3 报告：episode 形态与 episode 级评测（2026-11-12，进行中）

> 用户口径：episode 为主单位（不设数量/长度硬指标、没活不硬整）；typed 降级为块内注释；
> 重建后旧记忆归档。设计见 `docs/MEMORY-V3-DESIGN.md`。

## 1. 已落地

- `dream.memorySchema = 'v3'`：默认作业 wash → episodes → people → lexicon → consume → cleanup → index；
- `episodes` 作业：按经历窗口产出 episode（标题 + 完整第一人称正文 + 证据 + 人物 + 注释 + 关系），
  加一次**同日合并/改写轮**（只合并同一段经历/主题，保留全部细节；没有可合并就 []）；
- `episode` 命名空间（label 经历）纳入 recall，命中时返回**标题 + 完整正文**；
- cleanup 的块范围改为 episode/person/slang，合并时**并集证据/注释/关系**（v2 时合并会丢证据）；
- entity/relation 同步覆盖 episode（people→entities、relations→关系边、正文关系词兜底）；
- eval harness 新增 `--schema v3`：episode 级 formation 指标（块数/天、正文长度、证据覆盖、注释数）
  与 gold→episode 证据映射（多对一：一个 episode 可同时是多条 gold 的答案；person gold 同时挂
  person 档案与覆盖它的 episode，两种读路径都能命中）。

### 2.2 第 2 轮新增：内容完整性指标与完整性约束

- v3 formation 新增 `goldContentRate / contentCompletenessAvg`：不依赖期望映射，直接看每条 gold
  的内容词有多少出现在最好的一块 episode 正文里 → 防止"命中率靠筛掉难例"的幸存者偏差。
- 首测：focus 内容完整性 47–56%（v2 未测同口径），说明合并/概括确实会丢一部分细节；
  QQ 仅 30%（材料稀疏 + 原子 gold 很多），live 87.5%。
- 同步加了硬约束：
  - episode prompt 明确"当天每段值得留下的经历都要写进某一块，不要因为合并漏细节"；
  - 合并轮若模型给的正文比原文拼接短于 80%，直接回退为原文拼接（宁长勿丢）；
  - 解析器加"截断兜底"：模型输出被 token 上限截断时，逐个解析前面完整的对象，救回部分块，
    不再让整天 job 失败。

### 2.3 第 3 轮：检索上限诊断（LLM 重排实验 + 候选扩召回）

- **上限实验**：把全部 30 个 episode 标题+正文开头直接给云端模型选 1–3 块（每 probe 一次调用），
  focus 14 个有期望 probe 上 **hit@5 = 92.9%**（当前 recall 同 run r5 67.9%）→ **差距主要在
  "候选生成/排序"，不在 episode 内容本身**；LLM 重排能把上限拉到 ~93%，但每轮召回加一次模型调用
  成本/延迟不可接受（生产不应默认这么干）。
- 已做（低成本、不调模型）：
  - episode 单独放宽一轮候选（粗块 embedding 相似度普遍低于原子块，严格 floor 会把正确块直接筛掉）；
  - person gold 同时挂 person 档案与覆盖其证据的 episode（修复 recall 探针永远不可能命中的映射 bug）；
  - 内容词增加 3 位以上数字与更高权重（端口号/群号类 queries）；
  - 期望映射最多 3 个 episode（多对一），减少"一块 gold 被拆到多块"的映射歧义。
- 当前 focus v3（同一 formation 上重排）：r2/r3/r4 三次样本 r5 = 77.4 / 90.5 / 74.3%，miss 7–14%；
  **方差仍大，尚未稳定超过 v2（86–88%）**。
- 下一轮优先方案：**episode 正文分段索引**（正文按 ~250 字切段、每段单独向量索引，命中段回映射到
  整个 episode）——用便宜方式获得"细粒度匹配 + 粗粒度返回"，目标把候选召回率拉到 LLM 重排上限附近，
  再决定是否保留 LLM rerank 作为可选项。

- 结论（当前证据）：**v3 在 QQ/live 明显优于 v2，focus 与 v2 持平（82.7–89.5 vs 86.3–88.2）**；

### 2.6 第 5 轮：可选 LLM 重排 + focus 多次采样（v3 vs v2 定论）

- recall 新增可选重排（`recall.rerank=off|llm`，默认 off；复用 dream-chat 槽位，槽位不可用自动跳过；
  eval 用 `--rerank llm`）。只对 top 8 候选做一次选择，失败保持原排序。

  同条件 v2 fresh 两次：r5 = 86.7 / 100%（均值 93.4）→ **focus 上 v2 检索仍优于 v3（约 +9pt）**。
- **v3 + LLM 重排**（fresh，三源）：

| 素材 | episodes | gold 覆盖 | r1 | r5 | miss | 同源 v2 r5 对照 |
|---|---:|---:|---:|---:|---:|---:|

| old-qq | 12 | 75.0% | 77.3 | **77.3%** | 18.2% | 76.9% |

### 2.8.1 关键口径：anyHit@5（任一正确经历块被召回）

粗粒度记忆下一条 gold 可能对应多个 episode，"全部期望块都召回"（recall@k）不是产品口径；
新增 **anyHit@k**：只要返回里出现任意一个正确经历块，这题就算"回忆得到"。
v2 的期望集基本是单目标（recall≈anyHit），因此可直接对比：

| 素材（重建库） | v3 recall@5 | **v3 anyHit@5** | v2 recall@5（≈anyHit） |
|---|---:|---:|---:|
| focus-core | 87.2% | **100.0%** | 86.7–100%（均值 93.4） |
| old-qq | 80.8% | **84.6%** | 76.9% |
| real-live | 94.4% | **100.0%** | 85.7% |

→ **按产品口径（任一正确经历块被召回），v3 三源均优于 v2**；focus 的 recall@5 较低只是因为
gold 被拆到多个 episode，返回一个正确块已能回答（miss=0）。
- 新增 **材料行覆盖** 指标（只统计进入 formation 的 raw-main 行）：focus 约 70%、live 约 65%；
  剩余未覆盖行大量是她自己的推理/工具指令/短应答（本就不该进记忆），说明"内容完整性"数字
  之前被这些行和 paraphase 拉低，不能直接当"漏写率"。
- formation 稳定性仍是长期项：episodes 22–30/5 天、正文 350–440 字，运行间方差存在。

### 2.10 第 8 轮（用户新课题 A+C）：记忆自知/召回行为 + 空日守卫

> 用户 2026-11-13 反馈：v3 解决了成块质量，但"Agent 不知道自己什么时候记得"，主动召回几乎不发生；
> 询问记忆体系分类、以及空日会不会硬整。同意按 A（召回行为/记忆自知）+ C（空日守卫）推进，
> 并要求**复用现有提示词装配（如 world status），不要另起炉灶**。

**A. 记忆自知 + 召回行为**
- 记忆状态接入**现有 world 状态总线**（`ctx.services.get('world').registerSource`）：
  `记忆：经历 67 段（10-22..11-11）；上次整理 11-12 形成 0 段；未结承诺 N；人物 12；语料 37。`
  每轮自动出现在 world 段，不新增提示词机制；细节用现成 `world_status owner=memory` 展开。
- 新增 `memory_status` 工具（沿用 recall 工具注册方式）：返回经历范围/最近 5 段/未结承诺/最近整理结果/
  未消化笔记，触发场景"在说自己不记得之前先看"。工具面 69→70、46,954→47,475 字符（测试已更新）。
- eager-recall 增**低置信提示**：有相关但低于注入阈值（0.33–0.5）时只回一行
  "你可能对「[经历] …」有相关记忆（不确定，仅供参考）；需要的话可以调 recall 查一下"，
  不注入内容；5 分钟冷却，日志记 `hint:true`。
- recall 空结果附"当前记忆覆盖 X..Y，共 N 段经历"，让 Agent 区分"真没有"还是"没搜到"。

**C. 空日/稀疏日守卫（没活不硬整）**
- `episodes` 稀疏守卫：无显式 note 且真人材料 <60 字 → `skipped: below-salience`，**不调用模型**；
- 小材料合并：总材料 <900 字时把多个经历分片合并成**一次**模型调用（此前 318 字也会切 5 片发 5 次空调用）；
- 实测 live 11-12：5 shards/318 字/0 episodes/empty=true —— 提示词约束本身有效，本轮把"空跑/硬整"
  从提示词约束补成确定性行为。

**验证**：全仓 **918 tests / 917 pass / 1 skip**；新增测试覆盖 world 状态行、memory_status、
低置信提示、稀疏日不调模型、小材料只发一次调用。以上改动需重启 DSH 一次生效。

## 3. 当前结论与问题

- **成块形态达标**：块大、上下文完整、非配额化（用户已确认"最接近理想记忆块"）；
  focus gold 覆盖 84.4%，live 87.5%，QQ 75–80%；同一段经历自然合并（合并轮）。
- **检索（产品口径 anyHit@5，任一正确经历块）：三源均优于 v2**（focus 100 / QQ 84.6 / live 100；v2 93.4 / 76.9 / 85.7）；全部期望块都命中的 recall@5 为 focus 87.2 / QQ 80.8 / live 94.4（
  focus 的 recall@5 略低于 v2 是因为一条 gold 被拆到多个 episode，但返回任一正确块即可回答，miss=0）。第 1 轮 93.6% 是映射水分，已修正；
  剩余 focus 差距来自"细节型问句"需要在更长 episode 里定位，不是块内容缺失。
- **评测映射噪声是主要假 miss 来源**：一处阈值修正就让 focus r5 +4.5pt、miss 归零；
  后续评测必须同时看"材料行覆盖/内容完整性"这类非映射指标，避免误判。
- **仍需解决**：
  - focus 细节型问句的粗块排序（segment 命中作为主分数/标题加权，用 --seed db 快速迭代）；
  - QQ 剩 2 个 miss 的归因（映射 vs 检索）；content completeness 的语义化（当前 bigram 口径低估 paraphrase）；
  - 三源重复采样方差（episodes 22–30/5 天，正文 350–440 字）；
  - live 切换等用户停 DSH 后执行；重排默认关闭（用户已决定）。
