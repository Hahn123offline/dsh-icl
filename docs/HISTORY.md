## 2. 每次重写解决什么、放弃什么

### dsh-qq → focus-core

- **解决**：桥接把"一个人"切成了 N 份——每个 QQ 会话一个 DSH 会话，人格连续但身份分散；
  四个运行模式互相打架；权限模型改了三轮（L1–L3 → 闸门 → 零审批 + 盒子），全绕在 1.3 万行的 `bridge.js` 里。
  真正想要的是"同一时刻只有一个我、只专注一处"。
- **放弃**：上游可 `git pull` 的纯净性、多后端抽象（SnowLuma / NapCat）、审批闸门体系、WSL 盒子。
- **代价**：核心变胖。`attention.js` 一个文件同时管焦点、积压、静音、预算、窗口、世界；
  同一条消息走 `pierce` 与 conversation loop 两条通道（日志里两次 "one message, one channel" 修复）。

### focus-core → icl

- **解决**：核心一胖，功能就耦合进装配层；`focus` 变成核心私有，QQ/MC 只能绕着长；
  一条消息两条通道；模型配置散落三处互相打架。→ 只留三条核心契约（focus / delivery / slots，外加 prompt），
  **零默认工具 + 动态工具面**，单一投递出口，插件只声明形状。
- **放弃**：GUI、QQ/MC 连接器、旧数据迁移、热安装/插件市场、情绪与精力模型。
- **关键分歧**：重构计划写的是"**单例 host + 多会话适配器**"，
  实际落地变成"**每个 DSH 会话各跑一份 `icl-live` 实例**"，于是又要用单实例锁去补。
  这是第三代最像第二代早期的地方。

## 3. 继承了什么

**代码只有一个文件是逐字节继承的**：`packages/adapters/dsh-client.mjs`（1008 行）
与 `dsh-qq/src/dsh-client.js` 的 SHA256 完全相同。而且它**跳过了第二代**
（focus-core 用自己的精简版），说明真正可复用的只有"和 DSH 说话的协议层"。

其余是三类抽象，不是代码：

| 类型 | 具体继承 | 落在哪 |
|---|---|---|
| 记忆 | 四层记忆与 recall_cues（早期调研自 MaiBot）、权重 / 半衰期、按在场人物注入画像 | `memory` / `recall` / `eager-recall` / `whois` |
| 注意力 | focus / pierce / 积压 / 预算 | `focus` 契约 + `time` 的加锁与排队 |
| 调度 | "调度层 vs 叙事层"分离、一条消息一个通道 | `delivery` 恰好一次 + 提示词装配 |
| 数据 | 170 条真实 QQ 聊天记录（`dsh-qq/state/memory.db`）当回放素材与冻结题库 | `tools/replay.mjs`、`tools/fixtures/bench-qq.json` |

**明确不继承**：`bridge.js` 的模式机、两张 30 万字符的单页控制台、WSL 盒子、审批体系、11 个 `qq*.js` 领域模块。

## 4. 能力对照

"差距性质"：**核心缺口**＝缺契约，插件补不了 · **插件层可补**＝契约够，只差插件 · **故意不做**＝计划内排除。

| 能力 | dsh-qq | focus-core | icl | 差距性质 |
|---|---|---|---|---|
| 人格注入 | ✅ | ✅ 改完下一句生效 | ✅ 版本 / 回滚，每轮求值 | 已覆盖且更强 |
| 记忆注入 | ✅ | ✅ | ✅ 四类召回 + 逐句依据 + 原文兜底 | 已覆盖且更强 |
| 世界注入 | 部分 | ✅（注意力/静音/预算都在 `attention.js`） | 基础版：只读总线，深度 2 | 插件层可补 |
| 工具注册 | ✅ | ✅ | ✅ 唯一通道、描述由约束拼装、按预设过滤 | 已覆盖 |
| 上下文压缩 | DSH 原生 | ✅ `icl-compaction` + `fold-runner` | ⚠️ 有插件，未在真实会话触发 | 缺口已补，未验证 |
| session-guard | ✅ 租约 + 孤儿回收 | ✅ | ⚠️ 有 `claimSession`，未必生效 | 插件层可补 |
| observer（入站事件） | ✅ | ✅ 订阅 `session/event` | ❌ 只有 `signals` 与 `dsh-raw` | **核心缺口** |
| QQ 连接器 | ✅ | ✅（11 个模块） | ❌ | 集成层，工作量最大 |
| MC 连接器 | ❌ | ✅ | ❌ | 集成层 |
| B 站 | ❌ | ✅ 18 KB | ⚠️ 子进程接缝，阻塞数十秒 | 插件层可补 |
| GUI | ✅ 两个界面 | ✅ 14 个 view | ❌ | 故意不做 |
| 语音 TTS/ASR | 半条链 | ✅ | ❌ | 故意不做 |
| 执行沙箱 | ✅ WSL2 隔离 | 弱 | ❌（`editor` 只有读写列，有路径逃逸防护） | 故意不做 |

## 5. 五条教训

每一条都在三代里重复出现过，值得写在墙上。

### L1 单例不是一个锁，是一个架构决定

三代都在同一个地方栽：dsh-qq 把一个人切成多个会话 → focus-core 加租约与回收 → icl 每会话一份实例 + 单锁。
原因相同：**"一个机器一个实例"是设计目标，但落地时总是先让每个宿主各起一份**，再用锁去补。
只要锁是可选的，"只开一个会话"就会变成人为约定，而人为约定在测试里第一轮就破了。

### L2 核心变胖的机制没变，只是换了个名字

第二代的病是 `attention.js` 一个文件七件事；第三代把它拆成 13 个服务，
但 `services.mjs` 仍有 655 行、44 个导出。**拆得更整齐 ≠ 更少**。
判断标准应该是"这个服务有没有第二个使用者"，而不是"这个概念重不重要"——
按这个标准，`focus`（零插件使用）、`presets`（只有 `default`）、`delivery.push`（零调用）都不该存在。

### L3 文档跟着代码跑，必然过期，然后变成负债

三代都留下了"权威说明书"：dsh-qq 的 `PROJECT_GUIDE.md`（称 1450 行、"唯一权威版本"）
**在本地已经不存在**；focus-core 的 `HANDOFF` 说"没有 QQ 接入"，两天后长出 11 个 `qq*.js`；
本仓库整理前 32 份文档里 5 份自称过期、审计查出 22 处与代码不符。
教训不是"要勤更新"，而是：**文档必须能被机器校验，否则一定会腐烂**。

### L4 端到端证据一次一次往后推，三期都没有

dsh-qq 推到"B6 产品形态重写"；focus-core 推到"ICL 重构"；icl 推到"接完 DSH 再说"。
每次都用"先把这一块做出来"换取短期进度，代价是**永远不知道整体是否成立**。
现在唯一的长链路证据是两次 5 分钟，其中一次作废。

### L5 跨代唯一的可复用资产是协议层

`dsh-client.mjs` 逐字节继承，其余全部重写。这不是浪费——前两代的领域逻辑确实耦合得没法搬——
但结论很明确：**下次 DSH 协议再变，这个文件会各自漂移**（本仓库一份、dsh-qq 一份，无同步机制）。
它应该是个独立包，加契约测试。

## 6. 旧文档归属

工作区根目录有 15 份 `dsh-qq-*.md` 与 3 份同源 `.txt`（`findings.txt`、`findings2.txt`、`audit-out.txt`）。
它们散在仓库外是**有意的**：dsh-qq 要能随时 `git pull` 上游，文档不能放进它仓库里。

| 桶 | 份数 | 内容 | 建议去处 |
|---|---|---|---|
| 只属 dsh-qq | 8 | 部署笔记、使用说明、审计报告、模式地图、魔改设计、沙箱盒子、B4、模型页交互 | `dsh-qq/docs/archive/` |
| 对 icl 仍有效 | 6 | 记忆层设计、记忆调度设计、记忆架构 B5、模型中心、调度核心 v2、路线图 | 已在本文与 [MEMORY.md](MEMORY.md) 吸收结论，原文可留在 `_stage/` |
| 已被取代 | 1 + 3 | 调度核心 v1、`findings*.txt`、`audit-out.txt` | 就地归档，不再维护 |

**不建议整包搬进本仓库**——8 份是 qq-bridge 的运维细节，搬进来会立刻变成第二套过期文档。
