# 做梦质量对比（固定素材）

素材：`tools/fixtures/quality-day.json`（21 条消息，上午/下午/晚上三段）
模型：deepseek-chat　脚本：`node tools/quality-run.mjs`

## 改前：wash 抽笔记，下游只读笔记

| 指标 | 数值 |
|---|---|
| 块数 | 3 |
| 正文平均 | 65 字（57–73） |
| 每块证据 | 1 条 |
| 块时间跨度 | 单点（10:02 / 15:24 / 21:40） |
| 人物 | 1 块 / 1 条笔记（只有曾嘉睿） |
| 词汇 | 6 条（含 白饭 / 白饭了 重复） |

问题：wash 从 21 条消息里只抽出 4 条笔记，下游只能看到这 4 条 → 块薄、证据少、漏人。

## 改后：当天原话完整成 log，各轮自己提取

| 指标 | 数值 |
|---|---|
| 块数 | 3（早/午/晚各一块） |
| 正文平均 | 130 字（112–144） |
| 每块证据 | 5–9 条 |
| 块时间跨度 | 10:02–10:10 / 15:20–15:26 / 21:40–21:52 |
| 人物 | 2 块 / 8 条笔记（周子涵、曾嘉睿） |
| 词汇 | 2–4 条（无「白饭了」这类重复） |

## 结论

1. **洗得越少，记得越少**：wash 是抽取型时，它的遗漏就是整条记忆的遗漏。
2. **原话当原料**：把当天原话完整存成 `day:<date>` 的 log，events 从它切块、people 从它找人，
   块自然变厚、证据自然变多、人不再漏。
3. wash 仍保留，但降级为"印象笔记"（优先级高于普通笔记），不再是唯一入口。

## 已知遗留

- people 会产出 8 条笔记、部分近重复（"装好了 PowerShell" / "装上了 PowerShell"），
  留给整理轮合并；下一步可以在提取时按 who+事实前缀去重。
- 词汇条数在 2–4 之间波动（模型每次挑的词不同），需要更稳的采集提示词。
- 块时间跨度现在由 evidence 指向的 log 行时间算出，不再依赖笔记。


## 再进一步：wash 只去 JSON，不做抽取（2026-11-03）

`wash` 现在只做一件事：把结构化 JSON 从当天原话里剥掉，按时间整理成完整 log。
不抽取、不裁剪、不转手。events / people / lexicon 各自从这份干净原话里取自己需要的。

同一素材的结果（deepseek-chat）：

| 指标 | 数值 |
|---|---|
| 当日 log | 21 行（完整） |
| 块数 | 3 |
| 正文平均 | 122 字（105–137） |
| 每块证据 | 5–9 条 |
| 时间跨度 | 10:02–10:10 / 15:20–15:26 / 21:40–21:52 |
| 人物 | 2 块 / 8 条笔记 |
| 词汇 | 2 条 |

结论：抽取这一步去掉之后，质量没有下降，反而更稳定（不再依赖 wash 恰好抽到谁），
而且少了一次模型调用。`stripStructured` 有独立测试（整条 JSON、行内 JSON、围栏 JSON、普通代码）。
