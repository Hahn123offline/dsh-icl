## 0. 终极目标与验收

让一个 ICL 人格会话**真的拥有自己的节奏**：该睡睡、该醒醒、有事做事、想玩 MC 时能自己开一局、被外部消息打扰时知道怎么处理，而系统在后台稳定运行、可诊断、可回放。

本轮五个工作流，各自的完成判据：

| 流 | 完成判据（可检查，不靠模型自评） |
|---|---|
| **W1 MC 闭环** | 后台 lab 里的真实 ICL 会话，从"想玩 / 被叫去玩"到 `mcb_join` → 真做任务（≥10 分钟）→ 安全 `mcb_leave`，连跑 3 次无卡死、无残留、无状态污染；受试会话自述"我知道现在能做什么、下一步怎么做"；失败模式（连不上/body 崩/低血/断线/任务失败）都有可读原因与恢复路径 |
| **W2 前缀缓存** | 有一份"插件向 DSH 会话投消息"的完整模型文档；有可复现的测量工具与基线数字（cache hit / prompt tokens / TTFT）；全量前缀失效次数显著下降且有数字；语义不回退（`npm test` 绿） |
| **W3 time** | 按"唤醒 → 醒了干什么 → 接下来怎么行动 → 长期日程"四问重审完整性；P0 缺陷修复；S2/S4/S5 场景过；静音/拦截/积压语义有测试 |
| **W4 QQ** | 研究 + 接入设计 + 只读入站接入（lab 里能收到私聊消息并进入 signals，**不发任何消息**）；发送路径在开关后，等用户单独批准 |
| **W5 其它插件** | 一份按"会不会毁掉她的生活感/专注"排序的审计清单；P0（噪声、静默失败、每轮体积）当场修 |
| **W0 受试会话** | 一个可驱动的常驻 ICL lab 会话；她的困惑（工具不懂、刚才发生什么、下一步）被收集成问题单，进入上面各流的待办 |

**验收只认证据**：`events.jsonl` / `tool/call` / `turn/end` / 状态文件 / 测试。模型自述只当"当事人反馈"（宝贵，但不算链路证据）。见 [SURVIVAL.md](SURVIVAL.md)。

## 2. 合作纪律

1. **各自工作区**：每人 `C:\DSH\icl-wt\<name>`（`git worktree add`），分支 `wt/<name>`；根目录 `C:\DSH\icl` 是集成区，只有 lead 合并。
   - 测试不需要 `node_modules`（测试路径零外部依赖）；需要时用 junction 指向根 `node_modules`。
   - 动别人 scope 前先在任务板/消息里通知；合并由 lead 做，合并后跑全量测试。
2. **任务板**：所有工作建 `team_task`，写清 `write_scopes`；依赖用 `blocked_by`。claim 后再动文件。
3. **改了插件代码，如何生效**：lab 是独立进程，重启 lab 即可（秒级）；**绝不通过重启 desktop 来验证**。
4. **证据落盘**：每次实验写 `docs/quality/<timestamp>.md` 或在 `.state/<run>/` 留 `report.md` + 原始 jsonl。结论带文件行号/seq。
5. **不静默失败**：新代码的 catch 必须要么上报（`core.service-error` / report()）、要么有注释说明为何可以吞。
6. **文档**：一个事实只有一个家；改行为时同步改对应文档，不新增"又会过期"的第四份。旧文档里设计不合理处**直接改**，不做补丁式兼容。
7. **不碰**：desktop profile / 用户正在玩的 MC 客户端 / 公共 QQ 群 / `bili`（本轮可选项，不接）。

## 5. 提示词分层契约（提案，待用户确认）

现状问题：`prompts/live.md` 把**人格**与**怎么用工具**混在一起；`mc:play` 段、`mcb_join` description、`live.md` 的 MC 章节三处重复同一件事；动态状态段与人格段混排。

目标分层（三个家，各管各的）：

| 层 | 文件/位置 | 内容 | 稳定性 |
|---|---|---|---|
| **人格** | `prompts/persona.md` | 她是谁、怎么说话、偏好、边界、为什么活着 | 全局常量，极稳定，**不出现工具名** |
| **仿真纪律** | `prompts/sim.md` | 她在这个运行时里怎么生活：醒来/睡觉/专注/记忆/自己决定要不要出门；工具**类别**的意义（注意力、日程），不写参数 | 较稳定 |
| **工具教学** | 每个工具的 `description` + `skills/*.md`（按需读） | 具体参数、失败怎么办、示例；MC 深文档进 `mcb_help` | 逐工具，不进全局 |
| **事实状态** | 各插件 prompt section | 只有当前事实（时间、位置、任务、待办），≤1–2 行，**只陈述不教导** | 动态，但放尾部且缓存友好 |

落地顺序：先拆 MC（最小风险），再拆 time/focus，最后把 `live.md` 收成 persona+sim 两份。任何一层改动由 lead 在任务板记录，避免三处再次分叉。
