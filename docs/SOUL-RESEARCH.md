## 2. 它到底有什么

它不是一个“人格状态机”，而是六个相对独立的系统：

| 系统 | 实际形态 |
|---|---|
| 人格 | 三层**静态**文件：项目 `AGENT.md` → 项目覆盖文件 → 全局 `AGENT.md`；按小节叠加或互斥；首轮 + 每 15 轮注入一次 |
| 记忆 | 每回合自动提取、模型改写成记忆卡、规则打分、清晰度衰减、按当前消息 bigram 召回、固定预算注入 |
| 心情 | 每回合调模型判一次 mood + 七情（开心/踏实/甜蜜/心疼/担心/难过/吃醋），90 分钟半衰，全局一份；每 N 轮往消息后挂一句语气 |
| 目的 | 四个驱动值（想弄明白/在乎/想分享/想搞懂）+ 从记忆提炼“没闭合的事”；“主动想起”，不是主动发消息 |
| 日记 | 开机/ watchdog 补前一天；公开/私密两篇；带当天情绪；可提取“明天想说的话”和“日记连续线” |
| 笔记 | 独立 markdown 笔记本，文件是真相、index 是缓存；只注入标题/字数/摘要，正文按需 `soul_note` 读取；30 篇/2 万字上限 |

它**没有**通用日程/节律系统：`diarySchedule` 已停用，只剩日记补写调度；不存在睡眠、静音、focus、长日程这些语义。这一块我们已有的 time/rhythm 更强，不应移植它的调度。

## 3. 值得学的地方

### 3.1 记忆：清晰度阶梯 + 注入措辞

它的核心不是“向量更先进”，而是**记忆衰减的可读表达**：

- 清晰 → 清楚 → 模糊 → 只剩印象 → 遗忘
- 一天只降一档，重要的降得慢，被提起会回升
- 模糊时注入“细节记不清了”，只剩印象时注入“好像有…但想不起来了”
- 不是删除，而是先变得“说不清”；遗忘的进 archive，之后还能查回

这比我们当前“有/无”的块更适合长期关系。可借鉴到我们已有的 memory/dream/recall，而不必重写存储。

它的自动提取是：**纯规则过滤 → 模型改写 → 规则打分**。关键细节：

- 过滤宿主注入上下文、桥接信封、自己的回显，避免自我强化
- 一次性事件和画像用不同入库门槛（event 70 / fact/preference/promise 42）
- 没有信息量就返回空数组，宁可少记
- 近似重复只记日志，不自动替换

这套“过滤 + 提炼 + 确定性打分”的理念可以借，但**每回合多一次模型调用**的成本要谨慎；我们的 dream 是批量沉淀，不一定要改成逐回合。

### 3.2 笔记：文件是真相，索引只是缓存

`soul_note` 的设计很干净：

- `notes/<标题>.md` 是真相，`index.json` 只是缓存，可重建
- 注入只给索引（标题/字数/摘要），正文按需读取
- write/append/read/list/rename/delete + 回收站
- 同名写入默认报错，不静默覆盖
- 30 篇 / 单篇 2 万上限；到顶拒绝，不静默淘汰
- 只能写 `agents/notes/`，路径穿越/保留设备名拦截

如果我们要做“她的笔记本”，这是合适的轻量参照，不需要客户端。

### 3.3 动态状态：心情是全局、可衰减、低频率露出

- 心情全局一份，不按 cwd 拆
- 判定值只吃 1/3 的慢动；七情 90 分钟半衰，mood 12 小时回落基准
- 心情语气**不是每轮挂**，默认 7 轮一次，且中档完全不挂
- 语气作为单独 user 消息（`soul-tone`），不写进 system prompt，避免缓存失效
- 末尾必带“这只是今天的状态，不是这个人变了”的隔离说明

这给我们一个重要边界：**动态的是“此刻的状态”，不是人设本身。** 人格文件一字节不动。

### 3.4 人格：静态分层，不是状态机

它的“动态人格”其实是误读：人格是静态 AGENT.md 分层，动态的只有 mood/purpose。  
真正可借鉴的是：

- 项目人格 + 全局人格的分层/覆盖
- 首轮 + 每 15 轮补注入，防止上下文压缩后“忘了自己是谁”
- 不每轮重发完整人格

### 3.5 目的：主动想起，不是主动发消息

四个驱动 + 未闭合的事；它明确没有推送渠道，因此只让模型“想起”，不替用户决定发送。  
这个边界值得保留：**主动性和发送权分开。** 我们已有 QQ 出站，更应遵守。

## 4. 不建议照搬的地方

| 项 | 原因 |
|---|---|
| 七情 + 每回合 LLM 判定 | 每轮固定模型调用，约 800 token；七维状态对“轻量”目标太重 |
| 日记补写调度 | 我们已有 time/rhythm + dream/raw；再引入一套日界线/看门狗会冲突 |
| 通用日程/节律 | 它没有；不要反向移植 |
| 客户端设置页 | GUI 已后置；它的设置页与 mood 图绑定，不适合直接拿 |
| 五张表情图/prompt/代码 | 许可 + 风格 + 没必要；我们要做自己的 |
| 每轮大段记忆注入 | 我们上下文已经很重；学“清晰度/预算”而不是学“每轮 3200 字” |

## 5. 对我们下一步的设计建议

### 5.1 先做“轻能量/上下文压力”，不做七情

用户真正的需求是**用上下文压力催睡觉**，不是全套情绪系统。建议：

- **energy**：全局 0–100，缓慢衰减；睡眠恢复；失败/熬夜/连续对话加速消耗
- **contextPressure**：当前会话上下文占用、连续 turn 数、历史增长速率；只作为 energy 的乘数/触发条件，不单独进提示词
- **sleep pressure**：energy 低 + contextPressure 高 + 时间晚 → 在 facts/短提示里给一句“该睡了”，不硬改人格
- **不调模型**：全部确定性计算；避免每轮 judge
- **低频露出**：只在跨阈值或每 N 轮注入一条 runtime-context，不改静态 system，保 cache

可选第二条轴（心情）以后再加，最多 1–2 个维度；不做七情。

### 5.2 笔记：先判断是否真的需要独立系统

我们现在有：

- DSH 原生工作区 `write_file`/`read_file`
- `memo`/`memos`：短备忘、待办式，存在 memory DB
- 没有“自由格式的长期笔记本 + 索引注入”

建议：

- 如果只是“她写点东西、以后能读”：**直接用工作区文件 + 现有工具**，不要再造系统。
- 如果希望“她自动知道有哪些笔记、按需读正文、长期不衰减”：做一个**很小的 note 文件插件**：
  - `<workspace>/notes/*.md`，文件是真相
  - 注入只给标题/字数/摘要（≤N 条）
  - list/read/write/append/rename/delete + 回收站
  - 上限 30 篇/2 万字，路径穿越拦截
  - 不做 GUI、不做定时、不做自动总结

这比整套 soul notes 轻得多，也符合“简单版”。

### 5.3 记忆：借“清晰度/不确定措辞”，不重写存储

- 在现有 memory block 上增加 `clarity` 或置信度字段
- 注入时对低清晰度块显式加“记不清了/只是印象”
- 召回时优先高清晰度，近期/重要降得慢
- 不引入每回合自动提取，先评估现有 dream 的覆盖；若要做，先在 lab 里做低频率候选提取

### 5.4 日程/节律：保持我们自己的

- 不移植 soul 的 diary scheduler
- 我们的 time/rhythm 已覆盖日程、睡眠、静音、focus、wake；soul 只有日记补写
- 若以后要日记，作为 dream 的一个 job，而不是新调度器

## 6. 建议的研究/实施顺序

1. **P0（现在）**：只落研究结论；不引入依赖、不复制代码。
2. **P1**：轻 energy/contextPressure + 睡前提示（纯规则，先在 facts 里露出）。
3. **P2**：记忆清晰度/不确定措辞（现有 memory 增量，不换存储）。
4. **P3**：可选极简 note 文件插件；先决定是否真的需要索引注入。
5. **P4**：如果 P1 有效，再评估第二个心情轴/目的机制；否则不做。

## 7. 一句话结论

`dsh-agent-soul` 最值钱的不是“大而全”，而是几个边界清晰的小设计：  
**静态人格 + 会衰减的记忆 + 低频情绪露出 + 文件真相的笔记 + 主动想起但不主动发送。**  
我们应借这些边界，用更轻的状态（energy/contextPressure）和已有的 time/rhythm 实现，而不是整包继承它。
