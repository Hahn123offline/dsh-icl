## 5. 沙箱研究结论（追加，2026-11-06 00:35）

`docs/SANDBOX-PLAN.md`（实测通过，代码未改）：**Phase 1 推荐 DSH 原生 workspace-write + 专用 workspace 目录**（`C:\DSH\her` + 一次性 `icacls /grant ai_admin:(OI)(CI)F`，或零 ACL 修复的 `C:\Users\ai_admin\ICL`；state 留在 workspace 外）。边界事实：
- 只是**写边界**，读/网络/进程可见性不限制（她仍能读用户全部文件，包括 `~/.dsh/.credentials.yaml`）；是否接受"读不限"是 Phase 2（专用 Windows 用户 / WSL）的分水岭。
- 写自己成功、写外面被拒（`FS_SANDBOX_DENIED` + 升权提示）、read-only 下 pwsh 进 ConstrainedLanguage、approval 有 asked/decided 记录；ACL 要求 workspace 由运行用户完全控制，`.state` 目录继承 ACL 会失败。
- **editor 是洞**（raw fs 绕过 workspace 边界，写外面变成"不在工作区"且 isError=false）→ 必须下线；换原生 6 件套（tool-fs/tool-fs-search/tool-pwsh）会净增 ~6.1KB schema/请求（约 1.5k tok），需要和第一屏净化一起权衡。
- 需用户拍板：目录与 ACL、产品改动（preset/`DEFAULT_PLUGINS` 去 editor）、desktop `permission.defaultPreset` 改 workspace-write（用户 profile，未改）、接不接受读不限、QQ 审批应答器（进程内会挡 UI / 外部 client 共存）。
