# 语料层（lexicon）：梗、黑话、说法与风格（设计稿）

> 现状：`slang` 命名空间只是能跑，不是最终形态。
> 本文记录讨论方向，尚未定稿，也未开始改代码。

## 一、它到底是什么

不是"梗库"，更接近**怎么说话的知识**：

| 类型 | 例子 | 来源 |
|---|---|---|
| 词义 | 「难绷」= 绷不住了 | 群聊、B站、网络 |
| 用法 | 这个词只在熟人局用、长辈面前别用 | 场景观察 |
| 内部黑话 | 「大记忆恢复术」= 补录长期记忆 | 本群自造，网上搜不到 |
| 说话风格 | 她最近爱用短句 + 反问 | 长期归纳 |

所以命名建议从 `slang` 换成 `lexicon`（语料），
`kind` 区分 `term / usage / style / fact`，而不是把所有东西塞一个字段。

## 二、桶（bucket）怎么分

两个轴，不要只用一个：

- **来源轴**：`conv`（哪个群/私聊）、`platform`（qq / bili / web）
- **主题轴**：`tags`（技术、游戏、校园…）

查询时两者可组合：

```
lexicon({ conv: 'group:1057812765' })       // 这个群的黑话
lexicon({ platform: 'bili' })               // 刷 B 站学到的
lexicon({ tag: '校园' })
```

## 三、字段（草案）

```json
{
  "term": "大记忆恢复术",
  "kind": "term",
  "meaning": "把旧聊天记录补录进长期记忆",
  "usage": "只在群里自嘲时用",
  "scope": { "conv": "group:1057812765", "platform": "qq" },
  "tags": ["内部黑话", "记忆"],
  "confidence": 0.9,
  "origin": { "conv": "...", "messageId": "..." },
  "freshness": "active | fading | dead",
  "evidence": [{ "type": "note", "id": 12 }]
}
```

关键点：**`confidence` 与 `freshness` 是两个独立维度**。
"没搜到"不等于"不是梗"——内部黑话的 confidence 可能很高但网上查不到。

## 四、维护：做梦单开轮次

1. **采集**：从当天对话里抽候选（新词、反复出现的说法）
2. **求证**：网上搜不到的，进 note 待办（"搜一下这个词"），
   与"明天问问他 xx"同属待办层
3. **归并**：同义合并、过气标记（`freshness: fading`）
4. **跨平台**：B 站/网页学到的也进同一个桶，只是 `scope.platform` 不同

## 五、检索与使用

- 专用工具 `lexicon(...)`：**批量返回**（一次给一簇，不是一条）
- 场景提示：进入某个群时，可提示"这个群的黑话可以用 group:xxx 搜"
- 跨平台：同一个词在不同平台可能有不同用法，按 `scope` 区分

## 六、边界：它不是人格，也不该变成人格

- 语料是**数据**，可以被检索、可以引用；写不写进提示词、怎么写，
  由人格层决定
- 风险：如果把"最近爱用短句"直接注入提示词，等于偷偷改人格
- 建议：语料层只提供"可查的知识"，**不自动注入风格**；
  风格是否外显，留给上线前的仿真契约

## 七、和现有命名空间的关系

| 现有 | 建议 |
|---|---|
| `slang` | 改名/升级为 `lexicon`，旧数据按 `kind: term` 迁入 |
| `event` | 不变（事件） |
| `person` | 不变（人物档案） |
| `note` | 不变（备忘/待办），承接"搜一下这个梗" |

## 八、待定问题

1. 桶按"群"还是按"话题"为主？还是两者都是索引维度？
2. 风格（style）要不要单独成 kind，还是只做 tags？
3. 过气（fading/dead）由谁判定：时间衰减、还是对话里不再出现？
4. 是否需要"这个词第一次出现在哪"的可追溯（evidence 已有，展示方式待定）
5. 和"知识"的边界：事实性知识（某事件、某技术）进 event 还是 lexicon？
