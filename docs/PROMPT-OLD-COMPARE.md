# 旧 dsh-qq 仿真提示词 vs 当前 ICL 提示词：长度与分层对照

> 目的：在给当前 `sim.md` 做瘦身之前，先确认旧项目那些长内容哪些是**该保留的能力**，
> 哪些只是**工具协议/群聊策略/人格越权**。避免为了"干净"把真正有用的经验削掉。
>
> 只读对照，不改产品行为。旧项目路径：
> `C:\DSH\qwenstuff\dsh-qq`

## 1. 体量对照

| 层 | 旧 qq-chat-v2 | 当前 ICL |

旧项目自身也分阶段：`qq-chat`（一代）仿真只有 2,079 字符；`qq-chat-tools` / `qq-chat-v2`
涨到 9,276 / 9,183 字符。膨胀主要发生在二代把"群聊行为协议 + 每工具操作手册"塞进
preset persona.prefix 的时候。

旧项目体量大头不在"人格自我介绍"，而在**群聊行为协议 + 工具操作手册 + 社交人格规则**三块。
当前 ICL 是私聊产品，很多群聊协议不适用，所以总量小是合理的；但要分清哪些是"暂时不用"
和"真的丢了"。

## 4. 旧项目哪些内容不该在瘦身中丢

### 4.1 应留在工具层（已基本对应）

- 发送分条、引用、图片、转发、戳、表情、语音、等待、水位、收尾——当前由
  `qq_*` 工具描述 + `qq_help` 承担；不要搬回 sim。
- 安全/权限：当前由工具边界（只 owner 私聊、群不存在、发送三把钥匙、消息 gate）
  承担；旧文案的"没有本地工具"不能照抄。

### 4.2 应留在人格层（当前人格偏短，未来扩展时补）

- 说话长度/节奏/AI 味黑名单/回复示例/人格梗：旧角色卡 §二–§七 有 3,500+ 字符，
  当前 `persona.md` 只有约 2,000 字符，覆盖了身份/语气/底线，但没有旧版那么多
  示例和黑名单。**这是"未来人格系统"的素材，不是仿真应承担的内容。**
- 主体性/该说/不该说：可保留为原则，但不要写成分条操作手册。

### 4.3 应留给未来群聊（当前产品不需要）

- 群聊不是客服队列、认人只认 QQ 号、群文化自适应、不当群管家、群聊节奏。
- 这些在私聊里不成立；等群聊真正开放时，做 `sim-group.md` 或群聊 skill，不要现在塞进
  base sim。

### 4.4 可压缩/删除的旧内容

- 旧工具协议里大量具体工具名/参数（`qq_get_unread_messages`、`qq_mark_read`、
  `qq_set_wake_config`、`qq_send_voice` 等）——当前工具面不同，且属于工具 description。
- "操作即动作，不是 API"这类元叙述，可由工具结果/系统提示自然承担；不必占全局段。
- 旧版对群聊/语音/表情的细碎频率规则（"3~5 轮一张"等）——属于工具/skill 或未来群聊策略。

## 5. 对当前 ICL 的结论

1. 当前 1.4k 的 sim 不是"把旧内容丢了"，而是把**工具手册**和**群聊协议**移走了；
   这两块本来就不该在 base sim。
2. 真正需要警惕的丢失是**人格层的说话示例/AI 味黑名单/主体性**。当前人格层偏短，
   等做人格系统时应从旧角色卡迁移，而不是从旧 sim 迁移。
3. 旧 sim 的人格越权问题是真的；当前 ICL 已把人设/语气收进 `persona.md`，方向正确。
4. 未来瘦身 sim 时，优先把 `recall`/`focus`/`MC` 的操作细节继续移回工具/skills；
   但不要把"生活节奏/专注/记忆"这些跨工具的生活纪律一起删掉。
