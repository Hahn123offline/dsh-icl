# 概览：这是什么、做到哪一步、卡在哪

> 读者：第一次接手、或隔了一段时间回来的人。
> 范围：只做定性与复盘，不含操作细节。操作看 [DEVELOPING.md](DEVELOPING.md)，事实看 [STATUS.md](STATUS.md)。
> 基线：2026-11-03，HEAD `d9b5f84`，132 个提交（2026-11-01 起）。

---

## 1. 一句话

ICL 是一个**会话里的"内里"运行时**：它不长在 DSH 外面，而是作为插件长在 DSH 会话里面，
替这个会话维护四样东西——**记忆、时间、人格、做梦**。

或者说：DSH 提供"她这一轮能想什么、能做什么"，ICL 提供"她之前经历过什么、现在几点、该睡了"。

## 2. 它不是什么

先把歧义排掉，这三条决定了后面所有判断：

| 容易被误认为 | 实际 | 证据 |
|---|---|---|
| 一个 agent 框架 | 不是。agent 循环、会话、模型调用都在 DSH 里 | 核心 9 个文件 1468 行，无模型循环 |
| 一个聊天机器人 / QQ 机器人 | 不是。它没有入站通道，一个连接器都没有 | 无 QQ / MC / Discord 代码；`bili` 只是子进程接缝 |
| 有界面的产品 | 不是。零 GUI、未部署、未上远程服务 | 仓库无前端；端到端只在本机以脚本驱动 |

它是**第三代**同名念头的实现（见 [HISTORY.md](HISTORY.md)）：第一代解决了"能通过 QQ 说话"，
第二代解决了"成为一个人"，这一代只解决"**契约**"——核心只管六个抽象（工具面、提示词段、
投递、槽位、原文源、上下文），其余全部下沉为插件。

## 3. 它要闭合的那个环

整个项目只有一条主线，其余都是这条线的配件：

```
       ┌──────────────────────────────────────────────┐
       │                                              │
  醒来 ─┤→ 做事（刷 B 站 / 聊天）→ 记住（笔记/记忆）→ 睡着整理（做梦）→ 再想起来
       │                                              │
       └──────────── 时间模块：什么时候醒、睡多久 ──────┘
```

四段各自对应一组插件：

| 段 | 谁负责 | 产物 |
|---|---|---|
| 醒来 | `time`（日程 / 唤醒 / 积压释放） | 一条 `wake` 信号 → 队列投递 → 会话新轮 |
| 做事 | 工具面（28 个工具：记忆侧 13、时间 7、B 站 4、文件 3、世界 1） | 工具结果 + 会话原话 |
| 记住 | `memory` / `note` / `lexicon` / `recall` | SQLite 里的笔记、块、人物、词条 |
| 睡着整理 | `dream`（7 个 job） | 事件块、人物档案、词汇条目、答疑待办 |

这条环**每一段单独都成立**，但**没有一次从醒来跑到再醒来**。这是理解这个项目现状的关键。

## 4. 资产盘点

用五级证据标注，后面所有结论都引这个口径：

| 级别 | 含义 |
|---|---|
| E0 | 只有文档说，没有代码或测试 |
| E1 | 单元测试（假宿主、临时 SQLite，不碰真实 DSH / 网络） |
| E2 | 假 DSH 集成（`fakeDsh` 只有 `tools.register` 与 `systemPrompt.section`） |
| E3 | 真实 DSH 会话里跑过（真实模型、真实会话日志） |
| E4 | 长时间运行（≥30 分钟或跨天） |

| # | 资产 | 规模 | 证据 | 备注 |
|---|---|---|---|---|
| A1 | 插件宿主 + 13 个服务契约 | 9 文件 1468 行；43 个测试文件 193 通过 | **E1**（`adapter-dsh` 到 E2） | 零运行时依赖；服务有 3 个从未被文档提及（`signals` `vision` `clock`） |
| A2 | 记忆与召回 | 6 个插件约 1300 行；测试最厚（14 个文件） | **E1** | 混合检索（向量 + 字面 bigram）、11 个命名空间、原文兜底 |
| A3 | 做梦流水线 | `dream` 995 行，7 个默认 job | **E1** + 固定素材跑过真模型（质量有数字） | 幂等键按天；重跑会整块覆盖同 summary 的块（见 [MEMORY.md §8](MEMORY.md#8-已知缺陷记忆侧)） |
| A4 | 时间与信号 | `time` 618 行 + `signals` 132 行 + 7 个工具 | **E1** + 真实会话定时器通过一次（5 分钟） | 控制后门（文件邮箱 + CLI）是本项目最实用的部分之一 |
| A5 | 人格化压缩 | `compaction` 77 行 | **E0**（只过单测，真实会话未触发） | 阈值 12000 字符，5 分钟会话压不到 |
| A6 | DSH 协议客户端 | 1008 行，从第一代逐字节继承 | **E3**（历史：dsh-qq 生产用过；本轮：`tools/dsh-session.mjs` 建会话成功） | 仓库内零测试、零调用方，是最脆弱也最不可替代的一块 |
| A7 | 内容产物 | `prompts/live.md` 45 行人格；两轮 5 分钟的真实行为记录 | **E3** | 唯一"效果"证据：她自己写了 10 条笔记，质量可读 |

**盘点的结论**：代码资产集中在"记忆 + 做梦"（A2/A3，约 2300 行 + 2400 行测试），
这是真正做过工程的地方；契约层（A1）干净但**大半空转**——`presets` 与 `delivery.push`
在代码里没有真实使用者，`focus` 只有 `time` 一个使用者。接线层（A5/A6）要么太薄（E0），要么全靠仓库外的插件。

## 6. 瓶颈

五条，每条都有可查的证据，不是感觉。

### B1 广度已经超过验证深度

16 插件、28 个工具、13 个服务、7 个做梦 job、7 个时间工具。而端到端证据只有**两次 5 分钟**，
且第一次因编排错误作废、第二次暴露了 `dsh-raw` 读错位置。**新增一块能力，可验证的表面反而更薄。**

### B2 真正的接线在仓库外

让 ICL 跑起来的三个前提——`icl-live` 插件、`icl-live` preset、DSH profile 的三处配置——
**都不在仓库里**，在 `~/.dsh/` 下。后果：

- 仓库内 `packages/adapters/*` 零调用方，CI 永远测不到它
- 新人克隆下来跑 `npm test`，全绿，但什么也不会发生
- 唯一知道"怎么接"的地方是三份文档，而它们互相矛盾（整理前的 `STATUS.md` B 区说"插件尚未加载成功"、G 区说"已接进 profile"）

### B3 文档曾经是思考工具，现在是负债

整理前 32 份文档 / 约 250 KB，其中 5 份自己写着"已过期"，审计查出 22 处与代码不符、
4 处文档之间自相矛盾。表现是：**每读一份都要先判断真伪**，判断成本已经高于重读代码。
（这次整理把 32 份收敛成 9 份 + 1 份归档，见 [DEVELOPING.md](DEVELOPING.md) 的文档约定。）

### B4 静默失败是系统性的，不是偶发

不是"有几个 bug"，而是"失败了不告诉你"：

| 位置 | 失败表现 |
|---|---|
| 装配期所有 `try/catch` | 空体，连日志都没有；提示词段出错就静默消失 |
| `delivery` 第 5 次重试 | 直接丢弃，不回队列、不推进水位、无计数出口 |
| `dsh-raw` 解压失败 | `catch` 返回空串，原文层整条失效且不报错 |
| `dsh-raw` 只解析 `user/message` 与 `assistant/message` | 工具结果（视频标题、UP 主、评论）**从来不在原文层**，于是人物记忆里永远不会出现 UP 主 |

对一个"记忆系统"来说这是最致命的形态：**记忆变薄时系统不报错，只表现为"她想不起来"。**
5 分钟测试里的 `people 0` 就是这个原因。

### B5 单会话假设没有强制

设计是"一台机器一个实例、只指向一个会话"，但 `host.claimSession` 只有 `icl-live` 调用，
仓库内没有任何东西阻止两个实例同跑一份记忆库与 `time.json`。第一轮 5 分钟测试正是因此作废
（两个会话共用一个工作区）。现在靠"只开一个会话"的人为约定。

## 7. 结论

**定性**：这不是一个半成品框架，而是一个**记忆与作息引擎**，外面裹了一层尚未被验证的接线，
上面盖了一层已经过期的文档。它的技术底子（契约、测试、审计纪律）比同类自研项目干净，
但它把力气花在"把每一块都做出来"，而不是"把一条线走通"。

三条路线，取舍在你要什么：

| 路线 | 做什么 | 代价 | 适合 |
|---|---|---|---|
| **A. 收口**（建议） | 冻结新增能力。把 `icl-live` 搬进仓库；跑通一次 ≥30 分钟的完整闭环（醒来→做事→做梦→再醒来），留下可复现的证据包；把文档里的事实改成可被测试校验的 | 2–3 天，期间不加功能 | 想让它**真的能用** |
| B. 继续铺 | 补 QQ / MC / GUI / 多连接器 | 每补一块，未验证面继续变大 | 想先看形态 |
| C. 降级为库 | 承认它只是"记忆 + 做梦"引擎，把时间、人格、接线交回 DSH，只保留 A2/A3 | 丢掉 A4/A7 的独立性 | 想减少维护面 |

推荐 A，理由不是"应该做完"，而是：**现在唯一缺的东西是证据，而证据只能由一条走通的线产生。**
在拿到那条线之前，B 的每一块新功能都无法被判断是否有效，C 也缺少"记忆到底好不好用"的判断依据。
